第一部分 · 首页修改完整方案

核心主张：首页布局 = 产品形态布局（天地盖：上两排四格菜 + 底部通栏米饭）。 用户一眼认出"我们就是这么一盒"，同时完成"今天下单"的转化。当前已产出高保真完整原型（一屏看完、含全部模块、点菜弹窗可交互），本部分即其方案固化。

1.1 设计原则：两层分离（来自 v0.4 定稿）

层级装什么本版处理
内容层
（这盒里有什么）		天盖日期 · 四格菜 · 米饭四格 1:1 实拍图 + 底部通栏米饭（纯展示，无任何控件）
决策层
（要几盒、付多少）		份数 · 应付 · 单价 · 上限独立"决策条"：份数 [− 1 +] ¥25.80 + 小字 ¥25.80/份 · 单笔最多 10 份

实物证据（最硬依据）：天地盖实物里没有任何一格可以单独加量——不存在"米饭两份、排骨一份"。 所以"份"只能是整盒的倍数，绝不可贴在某道菜旁边。v0.3 把份数塞进饭位 → 被读成"米饭要几份"，即层级错配，v0.4 已修正。

1.3 点菜弹窗定稿（用户最新指令）

交互：点任意菜格 → 底部滑出该出品方实拍照片墙

你最终拍板：弹窗不要菜品介绍文字、不要资质文字行，只展示供应商的 营业执照 / 门头 / 大厅 / 厨房 四张照片（2×2 占位）。这是把"看资质"从供应商页吸收进首页的最简实现。

  • 头图：菜名 + 来自哪家（认菜、知是谁做的）。
  • 照片墙：2×2 四格，标题固定为「营业执照 / 门头 / 大厅 / 厨房」，每格下方标「示意 · 待上传实拍」。
  • 数据来源：照片为占位；落码时由 U1 下发该供应商真实的四张实拍图（建议新增供应商照片字段，或在现有资质对象上扩展）。

合规提示：营业执照照片属于"资质以图呈现"，同样受平台审核约束；但它是 ABox 自有供应商的资质展示，不涉及第三方平台禁令。编号等敏感信息由照片本身承载，不另写文字。

1.4 功能要点（逐项）

  • 顶部倒计时（保留并强化）：深棕底、金字等宽数字、下圆角；取值纪律——取不到整行不显示、不回落写死值。
  • 产品形态即首页：天地盖 2×2 + 通栏米饭，所见即所得。
  • 四格实拍图（硬前置）：四张 1:1 俯拍图，后台菜品管理填 imageUrl。契约已存在（home.dto.ts 有 imageUrl、meal.service.ts 已下发），无需改后端、不加表。
  • 份数 / 应付决策条：控件带"份数"语义主语，不误读为某道菜的份数；单价回填小字行。
  • "来自：X ›"：高保真原型保留跳转溯源页（不动后端）；弹窗照片墙已就地吸收资质查看，两者并存不冲突。
  • 既有模块全保留：骨架 / 团长身份横幅 / 跟随团长卡与佣金明示 / 无团长引导 / 最大份数提示 / 已订概览 / 主按钮 / bottom-bar / 空态分级——只做布局改造，不删不减。

第二部分 · 供应商页修改完整方案

原页面唯一功能 = 展示供应商资质（许可证号、有效期）。被砍掉跳转外卖后更显单薄，现又被首页点菜弹窗照片墙高度重叠。 本部分给出全 29 方向穷举（你要求"所有可能性都提供给我选"）+ 重新定位推荐。

边界原则：首页是"今天下单"的转化页，供应商页应是"明天期待 / 品牌信任 / 增量营收"的内容页或工具页——各司其职，不抢同一块屏幕、不重复下单控件。

2.2 重新定位推荐组合（P0/P1/P2）

方向 A ·「明日出餐阵容」预告页 P0 主定位 零合规风险

页面定位：预售制下的"明天吃什么"内容页，承接首页"今日下单"之后的期待感。首页答"现在订什么"，本页答"明天谁来做、值不值得期待"。

功能要点：明日四格菜的厨房来源预告（与首页四格对应，不重复下单）· 厨房人物卡（主厨故事，非冷证件）· 行为数据信任凭证（"这栋楼吃过 860 次"替代证件号）· 订阅"明日菜单提醒"（微信一次性授权订阅消息）。

为什么专业：与首页不重叠；纯展示无第三方跳转，合规安全；复用现有 dishes/supplierName 数据，零新增契约。

方向 C ·「这一盒的来路」深度溯源 P1 深化

页面定位：品牌信任页，讲"食材从哪来、谁做的、怎么到手上"，服务高端极简调性。 建议 C 作为 A 的深化模块（点厨房人物卡展开来路），而非独立成页，避免页面过多。

方向 B ·「到店券 + 核销」营收页 P2 探索 需先解定性

页面定位：把 ABox"别人拿不到的写字楼午间流量 + 信任"变现的轻资产营收页。这是此前对话里唯一真正成立的创意。

核心专业增量（原创意专家完全没提）
若 ABox 帮合作商家"发券并抽佣"，极易被认定为网络食品交易第三方平台 → 触发 EDI 证 + 第三方平台备案 + 二清（整套创意最大雷）。

安全做法（二选一）：① 自营买断：ABox 采购买断券再作为自有权益发放，性质变自营营销； ② 广告/引流服务：明确是广告而非交易，券在商家系统完成，ABox 只收广告/服务费（且小程序内不得出现第三方平台名/标识/链接/可跳转物/可复制口令）。

2.3 与首页的边界（不重叠原则）

页面核心问题动作禁止
首页今天订什么 / 付多少转化（下单）不做内容故事、不做核销
供应商页（新）明天谁做 / 为什么信内容 / 信任 / 增量营收不重复下单控件

2.4 若你最终保留"来自：X ›"跳转（供应商页未冗余）

则第一部分弹窗照片墙仍保留（作为首页内的快速查看），供应商页从"重新定位"转为"增强"：保留资质/照片展示，叠加方向 A 的"明日出餐阵容 + 厨房人物卡 + 订阅提醒"，把"冷证件页"升级为"有温度的出餐档案页"。方向 B（到店券）仍可作独立入口，不依赖首页是否吸收资质。

2.5 供应商页待拍板项

  • 首页弹窗照片墙上线后，供应商页"看资质"功能是否彻底移除入口？—— 决定本页是"重新定位"还是"增强"。
  • 29 方向里先落地哪几个？我推荐优先 1.1 阵容 + 2.1 食安透明台 + 2.2 数据墙 + 7.1 少饭公益（零/低风险、复用数据、直接解"单薄"）。
  • 方向 B 的定性（自营买断 vs 广告服务）需法务确认，是 P2 能否启动的前提。

第三部分 · 统一落地路径与 Open Decisions 汇总

3.1 首页落码清单（纯前端，不动契约）

  1. 后台菜品管理上传四张 1:1 实拍图，写入 imageUrl（字段已存在）。
  2. index.vue：倒计时保留；天盖概念卡合并为"天盖"；四格菜改 2×2 网格 + 通栏米饭。
  3. 份数与应付合成独立"决策条"，带"份数"主语；单价回填小字行。
  4. 点菜弹窗：底部 sheet 改为供应商四张实拍照片墙（需 U1 下发供应商照片字段，或复用现有资质图片）。
  5. "来自：X ›"保留跳转；团长两块、已订概览、空态分级等既有模块不删。
  6. 真机核对首屏高度（iPhone X/11 / SE），重点验证 798px 推算。

3.2 供应商页落码清单（取决于 §2.5 拍板）

  1. 若重新定位：以方向 A 为主框架，接入明日阵容 + 厨房人物卡 + 行为数据墙。
  2. 食安透明台（2.1）可复用首页弹窗已有的四张照片，做"活证件"呈现。
  3. 少饭公益（7.1）对接现有"可备注少饭/免饭"功能，做轻量公益叙事。
  4. 方向 B（到店券）单独评估，需法务定性后再立项。

3.3 不变项（本次修改不触碰）

  • 预售制 T-1 截单 / 次日送达的业务规则与后端逻辑。
  • 单一套餐（一饭四菜）的定价 ¥25.80 与佣金计提结构。
  • 团长佣金归属与结算通道（已具备自动结算）。
  • 用户信息收集边界（不收集真实姓名、不进用户表单的配送位置）。
