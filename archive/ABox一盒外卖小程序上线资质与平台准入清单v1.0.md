# ABox 一盒 · 外卖类小程序上线资质与平台准入清单 v1.0

> **文档性质**：上线前置条件的**自查与决策清单**，非法律意见。审核规则以微信公众平台后台提示与市场监管部门口径为准。
> **编制日期**：2026-09-16
> **主体**：北京巡礼之年科技有限公司（昌平区）
> **前置背景**：公司已上架过**电商类**小程序；本次为**餐饮 · 外卖/点餐**类小程序
> **本版最重要的三句话**：
> 1. **工商经营异常是当前唯一的一号阻塞项** —— 不解除，ICP 备案秒拒、EDI 与食品许可均无法推进。
> 2. **资质成本高不高，取决于一个定性问题**：自营（单一品牌 + 合作门店）还是平台（多商家入驻）。两者成本差一个数量级。
> 3. **2026-06-01 生效的新规禁止"异地代工出餐"** —— 现有"供应商代工 + 集散中心打包"模式需要重新做合规设计。

## 一、能复用什么、不能复用什么

**这是你相对纯新手的最大优势 —— 但复用的边界必须分清。**

### 1.1 可直接复用（省时间）

| 项 | 说明 |
| --- | --- |
| 企业主体身份 / 微信认证 | 同一营业执照主体，认证资格有效期内直接复用 |
| 对公银行账户、法人身份证、经办人授权 | 材料层面直接复用 |
| 服务器与 API 域名的 ICP 备案 | 若外卖小程序复用同一域名/服务器，域名备案可复用 |
| 微信支付商户号 | 可复用，但需核对是否已开通"食品/餐饮"经营类目 |
| **EDI 许可证**（若旧电商为多商家入驻平台） | ⚠️ **最高价值的复用项**，见 §1.2 |

### 1.2 需先核查的一项（可能省掉 1–2 个月）

**旧电商类小程序当时走的是"自营"还是"多商家入驻平台"？**

- 若当时是**多商家入驻平台** → 公司**很可能已持有《增值电信业务经营许可证（EDI）》**，甚至已做过**网络食品交易第三方平台备案**。
  → 那么"平台路线"的最大门槛（EDI：注册资本 ≥100 万、3 名员工社保、境内服务器、符合业务场景的网站）**你已经跨过了**。
  → 但**仍需办理"变更/新增业态"**：网络食品平台备案的备案号中，第 2 位主体业态代码 `1 = 网络食品销售`、`2 = 网络餐饮服务`。原备案大概率只覆盖"食品销售"，**必须先变更增加"网络餐饮服务"业态**。
- 若当时是**自营零售** → 上述两项都没有，需重新评估路线。

> **行动**：登录旧小程序后台 + 翻查公司资质台账，确认是否持有 EDI 许可证及其业务种类表述、是否有"京网食备"备案号。这一步做完，后面的成本判断才有意义。

### 1.3 绝对不能复用（必须重新办）

| 项 | 为什么不能复用 |
| --- | --- |
| **小程序备案（ICP 备案）** | **逐个小程序独立备案**，旧的备案不覆盖新小程序 |
| **服务类目** | 电商类目与餐饮类目的资质要求完全不同 |
| **《食品经营许可证》** | 电商类目不需要，餐饮制售类目是硬要求 |
| 小程序后台的隐私指引、注销入口、客服入口 | 每个小程序独立配置 |

## 二、核心分歧点：两条路线，成本差一个数量级

**先把这个定性问题定下来，否则资质清单无法收敛。**

### 路线 A · 自营（单一品牌 + 合作门店）

用户全程只看到 **ABox** 一个品牌；合作方（三味屋等）以**代工/供货**身份出现，不直接面向用户开店。

- 微信类目：`餐饮服务 → 餐饮服务场所 / 餐饮服务管理企业`
- 需要：**《食品经营许可证》（热食类食品制售）**，或走"平台与门店管理关系"路径（见 §3.2）
- **不需要**：EDI 许可证、网络食品交易第三方平台备案、ICP 许可证
- 成本：最低。周期主要以食品许可 + 小程序备案为主。

### 路线 B · 平台（多商家入驻）

合作方作为**入驻商户**在平台内经营，平台提供入驻渠道、抽成撮合。

- 微信类目：`餐饮服务 → 外卖平台`
- 需要：**《网络食品交易第三方平台备案》** 或 **《网络餐饮服务第三方平台备案》**（2 选 1）
- **前置硬条件：必须先持有 EDI 许可证**（**拿 ICP 证代替 EDI 会被直接退回** —— 这是北京最高频的驳回点）
- 额外义务：食品安全总监 + 专职食品安全员、独立食安机构、**每 6 个月实地复核入网商户**、每年 1 月/7 月向省局报送入网商户资质
- 成本：高。EDI 办理 + 备案 + 持续合规人力。

> ⚠️ **两条路线都与现有技术方案有冲突，见 §四。**

## 三、逐项资质清单（适用场景 + 办理要点）

### 3.1 主体与工商基础

| # | 事项 | 适用场景 | 办理要点 |
| --- | --- | --- | --- |
| 1 | **营业执照经营范围补充** | 无论哪条路线 | 需含"**餐饮服务**""**食品销售/食品经营**"等表述。缺项会导致微信类目、食品许可、EDI 全部卡壳。**先改照，再办其他** |
| 2 | **移出经营异常名录** | **一号阻塞项** | 见 §五，必须先做 |
| 3 | 法定代表人身份证 | 微信认证、备案、许可 | 需在有效期内；身份证过期会触发备案注销（2026 新监管动作） |

### 3.2 《食品经营许可证》—— 本项目最核心的一张证

| 项 | 内容 |
| --- | --- |
| **适用场景** | 自营路线（路线 A）拿餐饮类目的**决定性材料**；平台路线的入网商户各自须持有 |
| **主体业态** | **餐饮服务经营者**；从事网络经营、中央厨房、集体用餐配送的，须在主体业态后**括号标注**（如"餐饮服务经营者（网络经营）"） |
| **经营项目** | 必须包含 **热食类食品制售**（现做盒饭属此项目） |
| **办理机关** | **区级市场监督管理局**（昌平区市场监管局），现场核查必不可少 |
| **有效期** | 5 年，到期前 **30 日**申请延续 |

**❗ 三个高频踩坑点**

1. **只有"预包装食品销售"不能过餐饮类目审核。** 若现有证照只覆盖预包装食品，必须申请**变更增项**为"热食类食品制售"。
2. **纯线上主体拿不到"热食类制售"。** 多地细则明文："无实体门店的互联网食品经营者不得申请所有食品制售项目以及散装熟食销售"。**你想自己持证做现做盒饭，必须先有真实的加工场所**，且场所地址须在营业执照载明地址范围内。
3. **网络经营要"报告"。** 从事网络经营的，应在开展活动后 **10 个工作日内**向所在地县级市场监管部门报告；网络经营情况发生变化也要在 10 个工作日内报告。

**⚠️ 若走"平台与门店管理关系"路径（路线 A 的变体）**：微信类目还接受"《餐饮平台与门店的管理关系声明》+《微信小程序餐饮门店运营资质和责任承诺函》（含旗下所有门店名单）+ 旗下所有门店的《食品经营许可证》"这一组合。**这条路必须能提供合作门店的真实《食品经营许可证》**，且平台要承担门店管理责任 —— 与 §四 的新规要求叠加后，责任相当重。

### 3.3 电信与互联网资质

| # | 资质 | 适用场景 | 办理要点 |
| --- | --- | --- | --- |
| 1 | **EDI 许可证**（增值电信业务经营许可证 · 在线数据处理与交易处理业务） | **仅路线 B 必需**；也是"网络食品交易第三方平台备案"的**法定前置** | 条件：内资公司、**注册资本 ≥100 万**、**3 名员工近 1 个月社保**、一级股东证明、经营场所证明、**公司名下已备案域名及证书**、**符合业务场景的网站**、无电信业务经营失信记录。法定审批周期长，实务约 20–45 个工作日 |
| 2 | **ICP 许可证**（信息服务业务） | 若平台含会员充值、有偿信息服务等经营性信息服务 | ⚠️ **不能替代 EDI**。做交易撮合，EDI 是硬性要求 |
| 3 | **小程序备案（工信部 ICP 备案）** | **所有小程序强制**，未备案不能发布 | 免费。企业主体要求：**营业执照状态正常、无经营异常**、法人手机号能接收 **12381** 短信。流程：信息填报 → 平台初审 1–2 工作日 → **12381 短信核验（24 小时内，超时驳回重排）** → 省通管局终审 1–20 工作日 |
| 4 | 域名 ICP 备案 | 后端 API 走自建域名时 | 备案主体须与小程序主体一致 |
| 5 | 等保 2.0（二级） | 涉及个人信息收集 | 建议二期完成；涉个人信息业务被抽查概率上升 |

### 3.4 平台准入（微信侧，全部为上线前必过）

| # | 项 | 要点 |
| --- | --- | --- |
| 1 | 服务类目选择与资质提交 | 商业类小程序**每月修改次数有限**（类目添加有次数与数量上限），**一次性选全，别试探性提交**。审核通常 3–7 个工作日 |
| 2 | 小程序备案 | 见 §3.3-3。**微信认证 ≠ ICP 备案**，两者都要 |
| 3 | 用户隐私保护指引 | **后台必填**，不填无法调用 `wx.login` / `getUserProfile` |
| 4 | 账号注销入口 | 隐私合规硬要求，**没有则不通过** |
| 5 | 客服入口 | 必须真实可达，审核会抽查 |
| 6 | 主体与资质一致性 | 所有上传资质的主体名称必须与小程序主体**完全一致**，包括括号、全半角 |
| 7 | 服务类目与实际功能一致 | 类目须能覆盖实际全部功能；有入口无内容会被驳回 |

### 3.5 资金与预付合规

| # | 事项 | 适用场景 | 办理要点 |
| --- | --- | --- | --- |
| 1 | **单用途商业预付卡备案** | **本项目余额账户 + 用户充值场景** | 北京市 2026-05-11 施行新办法，**行业含餐饮业**；**预收资金余额达 20 万元的，应当向区商务局备案**（未达可自主备案）。材料：备案表、预付卡合同、承诺书、营业场所房屋租赁合同。分公司发卡规模计入总公司，由总公司统一备案 |
| 2 | 预付卡限额与存管 | 同上 | 国家办法口径：单张记名卡 ≤5000 元、不记名卡 ≤1000 元；记名卡不得设有效期。规模发卡企业需按比例做预收资金存管 |
| 3 | 微信支付商户号经营类目 | 全部 | 核对是否已开通餐饮/食品经营类目，未开通需补交资质 |
| 4 | 发票链条 | 全部 | 供应商须开增值税发票（否则采购成本不能税前扣除）；团长佣金侧由灵活用工平台开服务发票 |

### 3.6 食品安全运行类（2026 新规新增，属硬门槛）

| # | 项 | 要求 |
| --- | --- | --- |
| 1 | **食安封签** | 餐饮食品须包装封口，**保证开启后无法复原**；平台须监督并拦截未贴/破损封签订单 |
| 2 | **互联网 + 明厨亮灶** | 监控须覆盖加工制作关键环节；**视频留存 ≥14 天**；平台列表页须展示"有/无明厨亮灶"标识 |
| 3 | **门店信息公示** | 主页显著位置持续公示营业执照、食品经营许可证、**实体门面实拍图**、实际经营地址 |
| 4 | **"无堂食"标识** | 不提供堂食的须在主页显著位置标注 |

## 四、⚠️ 2026 新规对现有模式的硬约束（本节最高优先级）

**《网络餐饮服务经营者落实食品安全主体责任监督管理规定》（市场监管总局令第 123 号）**
—— 2026 年 1 月 27 日公布，**2026 年 6 月 1 日已施行**。

这是本清单里**唯一可能推翻现有业务设计**的内容。

### 4.1 新规红线

| 条款要点 | 对 ABox 的影响 |
| --- | --- |
| 入网餐饮服务提供者**必须具有实体经营门店**并依法取得食品经营许可 | 无实体厨房就不能对外供餐 |
| **证照地址 = 线上登记地址 = 实际出餐地址，三者必须完全一致** | 现有"平台统一对外、供应商分散出餐"存在地址不一致风险 |
| **禁止家庭作坊、异地代工出餐** | ❗**"供应商代工出餐 + 集散中心打包"模式需要重新做合规设计** |
| 网店名称须与实体门面**招牌名称一致** | 若对外只打 ABox 品牌而门店招牌是"三味屋"，名称对不上 |
| 使用虚假/他人资质入网，**最高罚 20 万** | 借用供应商证照对外经营风险极高 |
| 平台方须配 **食品安全总监 + 专职食品安全员**、设独立食安机构 | 若定性为平台，须新增岗位与制度 |
| 平台方须**每 6 个月**实地复核入网商户 | 持续性人力投入 |

### 4.2 由此产生的一个必须回答的问题

**ABox 到底是"入网餐饮服务提供者"还是"平台提供者"？**

- 若为**入网餐饮服务提供者**（自营）→ **必须有自己证照地址下的实际出餐场所**，"异地代工"被禁止。现有 4 家供应商代工模式**不可直接沿用**。
- 若为**平台提供者** → 4 家供应商各自作为入网商户，须各自满足"实体门店 + 三地址一致 + 门店招牌与网店名一致 + 明厨亮灶"；平台须承担审核、复核、报送、封签监督等全套义务，且**EDI + 平台备案**不可避免。

> **建议**：在投入任何资质办理费用之前，先由法务出具一份**定性意见**，覆盖两层：
> ① 微信类目定性（自营 vs 外卖平台）；
> ② 123 号令下的身份定性（入网餐饮服务提供者 vs 平台提供者）。
> 这两层定性**决定了后面所有资质的组合与成本**，做反了等于白花钱。

## 五、一号阻塞项：工商经营异常与税务非正常

**这是当前唯一让"其他事都做不了"的问题，必须先解决。**

### 5.1 后果链条（已核实）

```
经营异常名录（2026-07 列入）
   ├─→ ICP 备案：管局系统自动比对工商库，人工无法干预、无法加急，直接驳回
   ├─→ 微信侧：平台按 2026「固源」行动全量核查，
   │            会「取消备案接入 + 限制被搜索」→ 新用户搜不到、分享卡片异常、有下架风险
   ├─→ EDI 许可证 / 平台备案 / 食品许可：初审即受影响
   └─→ 旧电商小程序：可能已被同样处置，需立即自查
```

**同时已知"曾为税务非正常户"** —— 税务异常通常是工商异常的触发原因之一，且未解除税务非正常状态，工商异常也移不出来。

### 5.2 修复顺序（不要跳步）

| 步 | 动作 | 注意 |
| --- | --- | --- |
| 1 | 解除**税务非正常户**：补申报、补缴税款与滞纳金、接受处罚 | 税务未清，工商异常移不出 |
| 2 | 向市场监管部门申请**移出经营异常名录**：按列入原因对应整改（补年报 / 办理住所变更或接受核查 / 处理处罚） | 不同原因材料不同，先查清列入原因 |
| 3 | 等待工商数据同步（约 **1–3 个工作日**） | 同步完成前提交备案仍会被拒，且可能留主体备案污点 |
| 4 | 核对工商系统显示为"**存续（在营）**" | 名称、地址、法人须与实际提交材料完全一致 |
| 5 | 再启动小程序备案、EDI、食品许可等申报 | 顺序颠倒会留下驳回记录，后续审核更严 |

### 5.3 立即要做的自查

- [ ] 登录旧电商小程序后台 → 设置 → 基本设置 → **小程序备案**，确认状态是"已备案"还是"已注销/取消接入"
- [ ] 若被限制被搜索 → 需先完成原注销流程同步（24–48 小时），再发起**重新备案**
- [ ] 若旧小程序已无可挽回，评估**新开一个小程序主体** vs 变更备案主体的成本

## 七、常见驳回原因与对应改法

| # | 驳回原因 | 改法 |
| --- | --- | --- |
| 1 | 资质主体名称与小程序主体不一致（含括号/全半角差异） | 逐字核对，扫描件清晰无反光遮挡 |
| 2 | 用《食品经营许可证》的"预包装食品销售"报餐饮类目 | 必须变更为含"**热食类食品制售**" |
| 3 | 拿 ICP 证代替 EDI 做第三方平台备案 | 北京明确退回，**必须 EDI** |
| 4 | 先上线后补备案，超过取得 EDI 后 30 个工作日期限 | 备案必须在法定期限内完成，否则责令整改 |
| 5 | 证照地址与实际出餐地址不一致 | 2026 新规硬红线，须三地址一致 |
| 6 | 无堂食未标注 / 网店名与门店招牌不一致 | 按 123 号令公示要求整改 |
| 7 | 功能不完整、有入口无内容 | 提交前跑通完整主流程（含下单→支付→退款） |
| 8 | 测试账号不可用 | 准备可用测试账号 + 审核说明文档 |
| 9 | 隐私保护指引未填 / 无注销入口 | 后台填写 + 开发注销功能 |
| 10 | 食品安全管理制度照搬模板、与实际业务不匹配 | 制度须贴合平台实际流程，否则被认定不具备可执行性 |
| 11 | 主体经营异常 | 前置修复（见 §五） |
| 12 | 诱导分享 / 外部支付跳转 | 不得引导至小程序外支付 |
| 13 | 未成年人相关内容缺少限制 | 声明不面向未成年人并做限制 |

## 八、待确认事项清单（决定成本的关键变量）

| # | 待确认 | 为什么重要 |
| --- | --- | --- |
| 1 | 旧电商小程序后台**备案状态**是否正常 | 决定是否需要先走注销重备 |
| 2 | 公司是否**已持有 EDI 许可证**、业务种类表述为何 | 可能省掉 1–2 个月与数万元成本 |
| 3 | 是否已有"**京网食备**"备案号及其业态代码 | 决定是新增还是变更 |
| 4 | 营业执照经营范围**是否已含"餐饮服务"** | 缺项则全链路卡壳 |
| 5 | 是否已有**实体加工场所**及其地址 | 决定能否自持"热食类制售" |
| 6 | 合作供应商的门店**招牌名称**是否与对外展示名称一致 | 123 号令红线 |
| 7 | 集散中心是否仅"打包"还是有"加工"行为 | 决定是否构成二次出餐主体 |
| 8 | 用户余额**充值规模**预计是否超过 20 万 | 决定预付卡备案义务 |
| 9 | 税务非正常解除进度 | 前置阻塞项 |
| 10 | 自营 vs 平台定性（法务意见） | 决定整个资质组合 |
