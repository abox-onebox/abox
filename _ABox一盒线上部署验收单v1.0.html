四、你要做的：小程序端改一行（三步）

后台我全包了；小程序必须你本机做 —— 构建产物在你电脑上，我够不着微信开发者工具。

  1. 改文件：abox-onebox/apps/miniprogram/.env，把这一行原文粘进去：
    VITE_API_BASE_URL=http://154.8.164.180:8080/api/v1
  2. 重新构建：在 abox-onebox/ 下执行 pnpm run build:mp
    必做 VITE_* 是构建期注入的，改完不重新构建等于没改 —— 这是小程序端和后台最大的不对称：后台 baseURL 走相对路径 + 容器 nginx 反代，零改动；小程序写死了 http://localhost:3000，必须换。
  3. 上传体验版：微信开发者工具 → 上传 → 填版本号与备注 → 到 mp.weixin.qq.com 把这次上传设为体验版。

六、上线前必须复核的三件事

① PROVIDER_MODE 已写 real（已确认）

这一项最容易出事：留 mock 的话，任意验证码免密登录任意身份 + 支付自动置为已支付，且全程零报错。 系统自带的 REQUIRED_IN_PROD 只防「漏配」，防不了「配成 mock」。已在 .env.prod 里显式写成 real。

② 8080 只给后台，别当公网 API 用

mysql / redis 没有映射宿主端口，只有 8080 对外。这个口现在只该给宿主机 nginx 反代用； 真上线要走「域名 + HTTPS + nginx 反代 8080」，届时把 8080 的公网放行规则收回。

③ 税务非正常户 还没确认

你确认的「经营异常解除」是 工商 那条线（gsxt）；税务非正常户是独立的一条线，解除与否目前没人确认过。 不影响现在联调，但正式卖餐前必须确认已解除，否则影响开票与对公收款。

七、本次真机暴露的一个仓库缺陷（待修）

不影响现在用，但下次重新构建镜像还会撞上，最好修掉。

根 package.json 有 "prepare": "node scripts/setup-husky.mjs" Dockerfile 只 COPY 了 package.json，没 COPY scripts/ ⇒ 容器内 pnpm install 报 Cannot find module '/app/scripts/setup-husky.mjs' 直接退出

本次是我在部署副本上把 scripts.prepare 摘掉后重建才过的。根治两条路，选一：

  • 推荐：Dockerfile 里补 COPY scripts/ ./scripts/；
  • 或让 prepare 判断文件存在性 / 只在有 .git 时跑 husky。

顺带说明：这类缺陷本地永远测不出来 —— 本地 scripts/ 就在那儿。这也是为什么真机首次部署必须真跑一遍，不能只在本地 gate.mjs 全绿就以为完事。
