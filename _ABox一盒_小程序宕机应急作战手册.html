ABox一盒 · 小程序宕机应急作战手册

当自研小程序临时不可用时，靠「团长转发 + 商家收款码」继续运营
修订说明：本版基于真实拓扑与项目本意重做——微信群里全是团长、没有普通用户；团长私下未必有用户群；以往是团长私聊发小程序链接给用户。团长才是唯一的用户触达节点。团员都是团长同事，团长认识每个人、知道送到哪。
三条铁律（贯穿全篇，任何文案/表单都不得违背）：
① 只供一个套餐——用户侧绝无"口味/选餐/备注"类输入字段（加了拖慢效率、违背本意）；但当日一饭四菜必须作为只读信息展示，让用户看到今天吃什么、避免盲订。
② 交付 = 团长取餐并送上楼——团员零走动，这是高分佣买的服务。文案里严禁出现"自提点 / 用户自提 / 自行领取"字样，统一表述为"团长送到你工位"。
③ 用户侧表单极简——只填 份数 一项。不采集配送位置（团长认识同事、自行送达）；不要求选"推荐团长"（表单本就团长专属，里面的单天然归该团长）；身份靠表单工具自动记提交人（昵称）+ 团长认识同事认领，全程不收集真实姓名。

核心判断：小程序只是"团长 → 用户"之间的连接器。你真正拥有的资产是——团长（人）、团长群（你的管理节点）、供应商（产能）、用户（需求）。小程序一停，团长直接把"轻工具链接 + 商家收款码"私聊/小群转发给用户，生意照转。难点不在工具，在于团长要逐个触达用户，所以一切设计都要让团长"转发越省事、用户操作越简单"越好。

一、先看清：真实的连接关系

一句话：小程序断了，团长不再发"小程序链接"，改成发"轻工具下单链接 + 商家收款码图片"。用户还是同一批人、还是团长那头触达，只是入口换了。下单只填一样——份数，没有口味选择（但表单会展示今日一饭四菜让你看），也不用填姓名（你是谁团长都认识，表单还会自动记提交人）；送到哪一层团长都清楚。付完款，团长会取餐并送到你工位，你坐着等就行。

二、先判断：到底是哪种「不能用」

情形表现还能用啥
情形1
自家服务器/代码故障		微信一切正常，只是 AB 自家小程序打不开微信内所有第三方工具可用（腾讯文档、问卷星、收款码）→ 最轻松
情形2
微信支付商户号冻结 / 备案出问题		小程序能开但付不了，或商户号被限微信沟通可用；改用个人/支付宝收款码
情形3
自家小程序被封		AB 小程序账号禁入，但微信聊天、群、第三方工具仍可用第三方表单 + 收款码；团长微信群完好
情形4
微信整体不可用（极极端）		账号被封或微信服务整体异常只能电话 / 短信 / 线下兜底

好消息：最担心的小程序挂了，几乎都落在情形1/3——这两种恰好微信生态内最容易用轻工具顶上，而且团长微信群永远不受小程序账号影响。

三、方案核心：给团长一套「可转发下单包」

因为触达用户只能靠团长转发，所以要把所有东西打包成团长一键就能发出去的三件套。你（商家）准备好一次，团长每天/每次直接转发。

团长转发包（三件套）

① 下单入口链接（团长专属）：一份长期有效的表单/收集表链接（腾讯文档收集表、问卷星、金山表单均可），每个团长用自己的那份。用户只填一项——份数（日期默认次日、单一套餐无需选餐；表单顶部只读展示当日一饭四菜）。不采集配送位置（团长认识同事、自行送达），不要求选"推荐团长"（表单本就团长专属，里面的单天然归他）；身份由表单工具自动记提交人 + 团长认识，不收集真实姓名。

② 商家收款码：一张商家官方收款码图片，用户直接付商家（不进团长口袋）。

③ 给用户的话术：极简两步（点链接填两项 → 扫码付），含截止时间，并明确"团长会送到你工位，你不用下楼"。

把这三件套存成团长的微信快捷回复 / 收藏，团长转发时只需粘贴，不用现编，既快又统一。

四、三套落地打法（按用户配合度分）

打法A · 用户自助：团长专属表单 + 商家码（首选）

链路：团长把"下单包"私聊/小群转发（用的是自己的专属表单）→ 用户点链接填份数→ 扫商家码付款（备注写昵称，非强制）→ 商家按"这是哪个团长的表单"自动归集结算 → 团长按熟悉的工位把餐逐层送上楼。

优点：最接近原体验；用户只填两项；数据自动成表；团长不碰钱；恢复后可批量导回。

难点：用户要"填+付"两步，部分惰性用户会掉单 → 靠话术极简 + 团长截止前逐一提醒老客户。

打法B · 团长代填：用户只说"要几份"（用户不会填时）

链路：用户私聊团长"我要2份" → 团长在自己的表单里代填一笔（记份数）→ 引导用户扫商家码付款（备注昵称，非强制）（团长只记份数，不碰钱）。

优点：对用户零门槛，转化不掉；团长掌握自己名下全部订单。

难点：团长工作量上升 → 把表单做成"团长专属快捷填"，或在团长小群里让用户接龙、团长统一代填。

打法C · 电话 / 线下（极端兜底）

链路：微信都不可用 → 团长电话统计（谁要几份）→ 团长取餐并逐层配送上门（应急现金代收仅作极端情形）→ 供应商按团长电话报数做餐。

优点：不依赖任何互联网。缺点：效率极低，仅情形4用；交付方式不变——仍是团长送上楼。

五、佣金怎么认定（关键）

表单本就是团长专属的——哪个团长发出去的表单，里面的单天然就是他推荐的，不需要用户再选一遍"推荐团长"。归因靠"表单归属"自动完成，两种落地：

  • ① 每个团长独立渠道链接（推荐）：问卷星/金山表单支持渠道参数（UTM）或多份副本，团长各拿专属链接，后台按链接自动归集到该团长，零人工。
  • ② 团长各自汇总报商家：团长把自己表单的份数报你，你按"谁报的"结算。最省事，仅团长数少、信任度高时短期用。

六、触达效率的缓解（本拓扑最大痛点）

没有统一用户群，团长要逐个私聊，慢且易漏。缓解四招：

1. 话术极简

用户只需"点链接填两项 + 扫码付"两步，降低掉单。

2. 存快捷回复

下单包存团长收藏/快捷回复，转发即粘贴。

3. 截止前提醒

团长对老客户逐一私聊提醒，别只发一次。

4. 鼓励拉小群

长期看，让团长把常点用户拉自己的小群，下次触达快十倍。

七、资金红线（务必看）

⚠ 红线：尽量不让团长用个人码「代收后转账」。长期代收形成资金池，带来税务、合规与信任风险。优先商家官方收款码，用户直接付商家；团长只做"转发 + 记录份数"，不经手钱。打法B里团长代填也只记份数、不收钱。
  • 短期不得不团长代收时，必须当天建「团长-商家对账表」，笔数金额逐条留痕。
  • 退款一律先记台账，恢复后用账户余额 / 补偿券处理，不私下退现金。
  • 每笔收款备注写昵称（非强制），方便团长核对；身份主要靠表单工具自动记录的提交人，不收集真实姓名。

八、数据留存与恢复

留存

商家每天从各团长表单导出备份。应急期订单不能只存在团长手机里。

恢复

小程序恢复后，按"表单归属的团长"批量补录系统，佣金结算不中断。提前和开发约好补录模板。

九、话术模板（可直接复制）

给团长的话术（你→团长群）

各位团长：ABox 小程序因【维护/通道调整】临时不可用，今明两天改「转发下单包」模式（见群文件/收藏）： ① 把「你的专属下单链接 + 商家收款码 + 下方用户话术」私聊或小群发给你客户； ② 用户填表（就份数一项）+ 扫码付（备注昵称，非强制）； ③ 不会填的客户，你代填一笔（份数），引导他扫商家码付（别收现金）； ④ 今晚24:00截单，截单后你去取餐，按你熟悉的工位逐层送到客户那； ⑤ 截单后把你名下份数报我。 佣金按"表单归属"照常算，不影响。辛苦各位！

给用户的话术（团长→用户，极简两步）

邻居好～ 一盒小程序临时维护，今天订餐改走这一步，明天照常由我送到你工位： 1️⃣ 点链接填：份数（就这一项，其他不用填） 2️⃣ 扫商家收款码付款（备注写昵称，非强制） 明天 11:30 前我会把餐送到你工位，你不用下楼，坐着等就行 🙏 截止今晚24:00，有问题直接私我
