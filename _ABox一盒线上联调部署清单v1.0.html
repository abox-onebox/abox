零 · 结论先行：这次可以不备案

这是本清单最重要的一条结论。它决定你是"今天就能开测"还是"等 1–20 个工作日"。

备案之所以绕不过，是因为两条规则叠加：域名解析到境内服务器必须备案、小程序正式环境只认已备案的 HTTPS 域名。 但这两条规则都有一个专门留给测试阶段的口子——腾讯云官方口径与微信的调试模式。

腾讯云官方文档原话

"若域名不解析到腾讯云中国境内云资源，仅通过服务器公网 IP 直接访问测试，可暂不备案。"

"只购买云服务器不使用域名，不需要备案。当您不使用域名解析指向服务器时，不需要进行备案。"

于是有两条路。建议两条并行：今天先走 A，让同事马上测起来；同时把备案提交上去（反正迟早要），备案通过后切 B。

对比项A 路径 · 零备案（本清单主线）B 路径 · 备案后（以后升级）
访问方式http://公网IP:8080https://域名
能不能今天测能，买完机器当天就能开测要等备案：腾讯云初审 1–2 个工作日 + 管局 ≤20 个工作日
小程序端同事需在体验版里打开调试才能请求接口后台配好合法域名，同事直接进，无需调试
后台端浏览器直接开 http://IP:8080，零门槛同左，只是换成域名
传输HTTP 明文HTTPS
代价同事每次重进要重开调试；明文传输等待周期，但一次到位
注意 A 路径下同事为什么必须开调试

微信在真机体验版会校验两件事：域名是否在后台的 request 合法域名列表里、域名是否已备案。 http://IP:8080 两条都不满足。右上角菜单里的"打开调试"正是微信留给内测的开关，打开后跳过这两项校验。

代价是：同事每次重新进入小程序都要重开一次调试。这是 A 路径唯一的日常摩擦点。

一 · 本次明确不做的事

先把这些划掉，你就知道这次的活儿有多小。

事项本次说明
域名 ICP 备案不做走 IP 直连，不触发备案拦截
小程序备案不做那是提审上架的前置，本次不上架
服务类目 / 提审不做体验版无需审核
食品经营许可不做前提是测试期间不真收款、不对外经营，见下方红框
微信支付商户号不做测试走免支付；体验版本身也不支持微信支付
EDI / ICP 经营许可证不做自营定性下本就不需要（2026-09-29 已裁决）
HTTPS 证书本次不做IP 无法签发正规证书；以后有了域名再配
硬红线 测试期间不要真收款

一旦同事在小程序里真实下单并真实付款（哪怕是 25.8 元），性质就从"内部联调"变成"对外经营"， 食品经营许可、明码标价、外卖新规那套义务会立刻适用——而你现在还没有证。

建议做法：测试期把价格置 0 或走线下结算，只验证流程与数据；真收款留到拿到食品经营许可之后。

二 · 十步操作（A 路径 · 零备案）

命令全部取自本项目真实的 deploy.sh、docker-compose.prod.yml 与 Dockerfile，不是通用模板。

A1买一台腾讯云轻量应用服务器 你做 · 控制台

腾讯云控制台 → 轻量应用服务器 → 新建。

机型
4 核 8G（建议一步到位，别买 2C4G）
地域
境内，选离北京近的（如北京 / 上海）
镜像
系统镜像 → Ubuntu 22.04（不要选应用镜像）
计费
包年包月。这次虽不备案，但以后备案要求时长 ≥3 个月，先买够省事
注意 为什么 4C8G 不能省

这台机上要跑 MySQL + Redis + API + nginx，而且要在机上构建两个 Node 镜像，构建峰值最吃内存。 2C4G 的典型症状是构建时进程被杀，报 Killed 且没有任何其它报错。

买完把公网 IP 记下来，后面全程用 你的公网IP 指代它。

A2防火墙只开两个端口 你做 · 控制台

轻量服务器 → 防火墙 → 添加规则：

端口用途是否必须
22SSH 登录必须
8080后台页面 + API 的唯一对外入口必须
80 / 443本次用不到不开
3306 / 6379MySQL / Redis绝不开
硬禁忌 3306 / 6379 一旦对公网开放

等于把数据库裸露在网上。这两个服务在编排里只走容器内网，宿主机不映射端口，不需要也不应该对外。

A3登录服务器并初始化环境 你或我 · SSH

本机有 OpenSSH，可直接在终端登录（把 IP 换成你的）：

ssh root@<IP>

① 固定时区（订单截单全靠它，错了会"差 8 小时"）

timedatectl set-timezone Asia/Shanghai && timedatectl | grep "Time zone"

② 加 2G swap（防构建期内存不足被杀）

fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab && free -h | grep -i swap

③ 装 Docker 并设置开机自启

curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

判据：两条都要出版本号，compose 必须存在（V1 的 docker-compose 不够用）

docker --version
docker compose version
A4拉代码 你或我 · SSH
cd /opt && git clone <你的仓库地址> abox-onebox && cd abox-onebox

判据：三个文件都得在

ls docker-compose.prod.yml scripts/deploy.sh .env.example
chmod +x scripts/*.sh
A5写 .env.prod 你填值
cp .env.example .env.prod && chmod 600 .env.prod

先生成两个随机密钥（各跑一次，输出抄下来）

openssl rand -base64 32
openssl rand -base64 32
nano /opt/abox-onebox/.env.prod
变量填什么
PROVIDER_MODE必须写 real 见 §4 红线一
JWT_SECRET上面生成的第一个随机串
MYSQL_ROOT_PASSWORD上面生成的第二个随机串（两个 MySQL 密码都要改）
WX_MINI_APPID小程序 AppID（微信公众平台 → 开发 → 开发设置）
WX_MINI_SECRET小程序 AppSecret（同上页面，只显示一次）
A6跑部署脚本 你或我 · SSH

先空跑一遍看有没有明显问题

./scripts/deploy.sh --dry-run

再真跑，约 8–15 分钟（含两个镜像的构建）

./scripts/deploy.sh
正常现象 首次部署 2/7 阶段报"备份失败"

因为还没有历史备份可备。属预期内，不是故障，继续跑即可。

A7验收三条判据 你或我 · SSH

判据一：四个容器都在跑（api / mysql / redis / admin）

docker compose -f docker-compose.prod.yml --env-file .env.prod ps

判据二：健康检查返回 ready

curl -s http://127.0.0.1:8080/api/v1/health/ready; echo

判据三：最容易漏 两支迁移都必须显示 [X]

docker compose -f docker-compose.prod.yml --env-file .env.prod run --rm --no-deps --entrypoint sh api -c \
  'node node_modules/typeorm/cli.js migration:show -d apps/api-server/dist/database/data-source.js'
硬禁忌 "部署脚本显示迁移已执行"不算数

必须亲眼看到 Init1700000000000 和 ParityFix1700000000001 两支都是 [X]。 TypeORM 找不到迁移时不报错、退出码 0，部署流程照样显示成功——而所有建表语句从未执行， 后面会表现为"接口通了但一查就空表错误"，排查方向会完全跑偏。

A8后台先自测：同事端的这一步是零改动的 你或我 · 浏览器

浏览器打开 http://<IP>:8080。

好消息 后台不需要改任何配置

admin-web 的接口基址写的是 import.meta.env.VITE_API_BASE_URL ?? '/api/v1'—— 不传就用相对路径，而容器内的 nginx 已经把 /api/ 反代到 API 容器。 所以只要 8080 能打开，后台就是通的。

服务端侧再确认一次页面能出

curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/

返回 200 即通过。这一步通过，后台就已经可以给同事用了。

A9把小程序指向服务器并上传体验版 本地 · 微信开发者工具
注意 小程序端这一步必须改，改了还得重新构建

与后台不同，小程序的基址是 import.meta.env.VITE_API_BASE_URL || 'http://localhost:3000/api/v1'—— 不设就指向 localhost，真机上必然请求失败。而 VITE_* 是构建期注入的，改完必须重新构建。

在 apps/miniprogram/.env 里写（没有就复制样例）

cd apps/miniprogram && cp .env.example .env
VITE_API_BASE_URL=http://<IP>:8080/api/v1
VITE_WX_MINI_APPID=<你的小程序AppID>

构建（在仓库根目录）

pnpm run build:mp

产物在 apps/miniprogram/dist/build/mp-weixin。用微信开发者工具导入该目录 → 右上角"上传" → 填版本号与备注。

A10加体验成员 + 生成体验版二维码 你做 · 微信公众平台

① 成员管理：mp.weixin.qq.com → 管理 → 成员管理 → 体验成员 → 添加，把同事的微信号加进去。

② 发布体验版：管理 → 版本管理 → 开发版本 → 下拉"选为体验版" → 生成二维码，发给同事。

人数上限
企业主体且未发布的小程序，体验成员 30–60 人（个人主体只有 15 人），内部测试够用
有效期
体验版本身不过期；但二维码 7 天有效，过期重新生成即可
权限
非体验成员即使拿到二维码也会被拦截，所以加人是必需步骤

三 · 同事侧：三步拿到可测版本

这段可以直接转发给同事。

C1后台：浏览器直接打开 同事做

手机或电脑浏览器打开 http://<IP>:8080，用你（管理员）分配的账号登录即可。 没有任何额外步骤，也不受小程序那套域名规则约束。

C2小程序：扫码进入 同事做

用微信扫你发的体验版二维码。若提示无权限，说明微信号没被加进体验成员名单，回去补 A10 第①步。

C3打开调试 同事做

进入小程序后：右上角 ··· → 打开调试 → 按提示重新进入。

注意 每次重进都要重开一次

这是 A 路径唯一的日常摩擦点。同事如果反馈"页面一直转圈 / 请求失败"， 先问有没有开调试——十次有九次是这个原因。

等备案通过切到 B 路径后，这一步就永久省掉了。

四 · 三条安全红线（公网必做，做完再发二维码）

服务器一旦有公网 IP，就不只是"你们能访问"，而是"全网都能访问"。下面三条不是建议，是必做。

红线一 PROVIDER_MODE 必须显式写 real

项目 .env.example 默认是 mock，其语义是：任意 code 免密登录任意身份 + 支付自动置为已支付。 在本机开发时这是便利；放到公网，等于任何人访问你的 IP 就能以任意身份登录后台， 而且服务照常启动、零报错，你不会收到任何提示。

REQUIRED_IN_PROD 只防"漏配"，防不了"配成 mock"。必须自己确认这一行写的是 real。

红线二 上线前扫一遍默认口令账号

种子数据里可能带开发用明文口令账号（dev_plain）。生产环境必须清掉或改密。

项目里有现成工具：apps/api-server/scripts/set-admin-password.mjs，直连数据库改 ab_admin_user.password_hash，不经 HTTP、不需要先登录——这点很关键， 否则会陷入"要改密码得先登录、登录又要密码"的锁死循环。

它必须在 api 容器内跑（MySQL 未映射宿主端口）。先跑 --scan 列出待处理账号，再改密并回读复验。

红线三 8080 是明文 HTTP

所有请求（含登录口令）在链路上是明文的。测试期可接受，但要清楚代价：

① 别在上面用真实的生产密码——给同事单独开测试账号；
② 若想收紧，可在防火墙把 8080 的来源 IP 限制为办公室出口 IP，或在 nginx 加一层 Basic Auth；
③ 备案通过切 HTTPS 后，这条自动解除。

五 · 以后升级到正式域名（B 路径）

备案是迟早要做的——它还是小程序上线的唯一不可压缩项。建议现在就提交，与测试并行。

序做什么周期
B1查域名备案接入商是不是腾讯云（决定走新增备案还是接入备案）今天 10 分钟
B2提交 ICP 备案，注意收到 12381 短信后 24 小时内完成核验，过期作废初审 1–2 个工作日 + 管局 ≤20 个工作日
B3备案通过后加 DNS 解析，指向这台服务器分钟级
B4certbot 签证书，宿主机 nginx 上 443分钟级
B5小程序后台配 request 合法域名（必须 HTTPS、不能有端口、不能用 IP）分钟级
B6同事从此免开调试，直接进体验版—

B1–B4 的逐条命令在《_ABox一盒后台从零部署腾讯云操作手册v1.0.html》的第 8 步里； 怎么查备案、怎么提交备案的图文步骤在《_ABox一盒备案与上云手把手图文指南v1.0.html》里，两份都在工作区根目录。

注意 切换时只有一处要改

小程序端的 VITE_API_BASE_URL 要从 http://IP:8080/api/v1 改成 https://域名/api/v1，改完必须重新 pnpm run build:mp 并重新上传体验版。 后台侧因为用的是相对路径，不用动。
