为什么 B 也能让同事各有各的账号（这点反直觉，值得知道）

mock provider 的规则是：dev:xxx → 固定身份；其它 code → 对 code 取 sha1 前 16 位当 openid。 同事真实 uni.login 拿到的 code 各不一样，所以账号也各不一样 —— 不需要 devCode，也不需要改构建命令。代价是微信 code 一次性，重新登录就是另一个人（token 有效期内不变，所以别退出登录即可）。

第 1 步新建 .env 文件（不是改，是新建）已完成
在哪儿做：文件夹 abox-onebox/apps/miniprogram/

我查过这个目录 —— 里面只有 .env.example，没有 .env。所以要新建，不是改。

做法：复制一份 .env.example，改名为 .env，然后把第 10 行改成：

VITE_API_BASE_URL=http://154.8.164.180:8080/api/v1

另一行 VITE_WX_MINI_APPID= 保持空着就行（我查了，这个变量在端上定义了但没有任何地方用它）。

为什么：小程序里写死了兜底值 http://localhost:3000/api/v1。不建这个 .env， 你同事手机上「localhost」指的是他自己的手机，必然连不上。建了它，请求才会打到 154.8.164.180。
为什么是 .env 而不是改代码：代码里那行兜底是给大家本地调试用的，动它会污染仓库；.env 已在 .gitignore 里，只影响你本机。
第 2 步重新构建已完成
在哪儿做：终端，abox-onebox/ 根目录（不是 apps/miniprogram/）
pnpm run build:mp
为什么必须重新构建：VITE_* 是构建期注入的 —— 构建时直接把值写进产物， 运行时读不到环境变量。改完 .env 不重新构建，等于没改。这是小程序端和后台唯一的差别： 后台的 baseURL 走相对路径 + 容器 nginx 反代，所以零改动就能上线。
为什么在根目录跑：build:mp 是根 package.json 的别名，它会先编 shared 包再编小程序； 进到 apps/miniprogram/ 里没有这个命令（那里只有 build:mp-weixin）。

为什么要导 dist 而不是 src：微信开发者工具只认编译产物（app.json / app.js / pages）， src 里是 Vue 源码它读不懂。第 2 步就是在生成这个目录。
别用「预览」代替「上传」：预览生成的二维码只能用一次、且有效期短，同事没法反复进；体验版是长期入口。
顺带安心：上传体验版不需要类目审核，餐饮 / 食品那套类目资质是正式发布时才要的，不影响这一步。
第 4 步设为体验版 + 加体验成员
在哪儿做：浏览器打开 mp.weixin.qq.com（微信公众平台）
  1. 管理 → 版本管理 → 开发版本 / 体验版本，把刚上传那次选为体验版。
  2. 管理 → 成员管理 → 体验成员 → 把同事加进去。
为什么要加体验成员：未发布的小程序只对这些人可见。（企业主体未发布：30–60 人；体验二维码 7 天有效。）
为什么必须走这条路：小程序没发布，所以不能用正式版；而服务器是国内未备案 IP， 不在小程序的 request 合法域名里 —— 靠下一步的「调试」绕开。
第 5 步同事每次进都要开一次调试
在哪儿做：同事手机上（你转告即可）
  1. 微信里打开体验版小程序。
  2. 右上角 … → 打开调试。
  3. 弹窗提示会重启小程序，点确定。
为什么非要这一步：调试模式会跳过 request 合法域名校验， 这是没备案的情况下唯一能让 http://154.8.164.180:8080 通的办法；顺带 HTTP（非 HTTPS）也能过。
代价：关掉小程序再进就要重开一次。这是用 IP 直连换来的必要成本，等备案 + HTTPS 之后就不用了。

三、做完怎么确认成了

  • 你手机开体验版 + 打开调试 → 能进首页、能看到菜品列表（说明接口通了）
  • 能下单 → 后台 http://154.8.164.180:8080 订单列表里能看到这条（说明写入通了）
  • 让一个不在公司 WiFi 的同事走一遍第 5 步 → 同样能下单（说明「不在同一 WiFi」这个目标达成）
mock 模式下的四个行为，转告同事前先看懂（不然会以为出 bug 了）
  1. 各人是各人的号：服务端按登录 code 算 openid，所以同事 A 和 B 是不同账号 —— 这是好事，订单不混。
  2. 别点「退出登录」：微信的登录 code 是一次性的，重新登录会拿到新 code ⇒ 换成一个新账号，之前的订单就看不到了。 只要不退出、不卸载小程序，token 存在本地，身份就一直是同一个（已核对：ensureLogin 有「已登录就不重登」的判断）。
  3. 7 天后会换号：token 有效期是 7 天，过期自动重登 ⇒ 换号。联调期注意这个节奏，别把 7 天前的数据当丢了。
  4. 支付会自动成功：不用真付钱也能走完下单全流程，方便测；但这意味着现在测出来的支付环节不代表真实情况，接了商户号还要重测。
同事打不开时，按这个顺序排查
  1. 他是体验成员吗？（不是 → 加成员）
  2. 他开调试了吗？（没开 → 一定连不上，因为域名没备案）
  3. 你自己现在打得开 http://154.8.164.180:8080 吗？（打得开说明服务没挂，问题在小程序侧）
  4. 还不行 → 让他把报错截图发我，我看服务端日志。

运营后台 http://154.8.164.180:8080 现在就能在手机浏览器里直接开，不用等小程序。 想让同事先看后台效果，今天就可以发这个地址。（后台移动端只做了关键路径，不是全功能。）
