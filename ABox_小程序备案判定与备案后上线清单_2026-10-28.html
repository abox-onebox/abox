二、为什么现在「上线不了」——贴证据

2.1 微信小程序侧三条硬规则（官方原文）

来源：微信开放文档《小程序 · 开发 · 基础能力 · 网络 · 使用说明》：

  • 域名只支持 https（wx.request 明文 http 一律不行）
  • 域名不能使用 IP 地址（局域网 IP 除外）或 localhost
  • 域名必须经过 ICP 备案

⚠️ 一条容易搞错的：官方明确允许带端口（https://myserver.com:8080 可以配）， 所以 8081 本身不是问题。真问题是「IP」和「http」这两条。

                 明文   裸 IP           （端口其实合规）

三、备案批下来后，必须做的 7 步（缺一步就白等）

第 1 步 · DNS 加 A 记录

api.xunlizhinian.cn → 154.8.164.180；admin.xunlizhinian.cn 同样指向。

注意官方另一个限制：不支持配置父域名，必须用子域名 —— 正好符合规划。

第 2 步 · 申请 SSL 证书

腾讯云免费 DV 证书即可（单域名证书申两张，或一张泛域名 *.xunlizhinian.cn）。

⚠️ 证书必须由受信任 CA 签发，自签证书小程序一律不认；证书链必须完整 （漏中间证书会出现「浏览器正常但小程序报 SSL handshake failed」）；TLS 版本 ≥ 1.2。

第 3 步 · nginx 加 443 server

新增一个监听 443 的 server，把现有 location /api/、/static/、/assets/ 以及已下沉到 location / 的 Cookie 闸门原样搬过去（nginx.conf:91 起那一整套）， 别只转发 API 却把闸门丢了。

保留 80 端口并做 return 301 https://$host$request_uri; 即可。

第 4 步 · compose 开 443
h5-prod:
  ports:
    - '${H5_PORT:-8081}:80'
    - '443:443'          # ← 新增
第 5 步 · 改小程序端地址
apps/miniprogram/.env:13
VITE_API_BASE_URL=https://api.xunlizhinian.cn/api/v1

⚠️ 走 443 标准端口时，后台配置里不能带端口，代码里也不能写 :443 —— 官方原文：「如果不配置端口，那么请求的 URL 中也不能包含端口，甚至是默认的 443 端口也不可以」。 直接写不带端口的形式最安全。

第 6 步 · 重新构建并重传

⚠️ 项目纪律里记着：deploy.sh 只 build api/admin， 小程序必须单独构建，否则端上还是旧包。且上线要用 --mode production， 别拿 development 包提审。

第 7 步 · 微信后台配 request 合法域名

小程序后台 → 开发 → 开发设置 → 服务器域名 → 填 https://api.xunlizhinian.cn（不带路径、不带端口）。

💡 这一步不用等备案完成也能提前做：备案前置检出的是域名是否已 ICP 备案， 你这个已经有了，可以先配进去预热。

四、提审前还得补的合规缺口（不阻备案，但阻巡检）

① 主页面资质公示被改掉了（124 号令要求）

pages/index/index.vue:97 的注释原文写着：

<!-- ⭐ 2026-10-24 整改（用户要求）：不再写「查看资质」，

而《网络食品安全违法行为查处办法》等要求入网食品经营者在店铺主页显著位置持续公示 许可证（或备案凭证）及可查验链接，明确覆盖「线上小程序」。 「来自：X」是供应商展示，不是资质公示，两者不能互相替代。 这一条和项目既有的合规待办（2026-05-20 施行的 124 号令）是同一件事，目前仍未收口。

② 销售页没有任何食品标签

全仓 .vue 检索「配料 / 保质期 / 生产日期 / SC 号」零命中。 预包装食品售卖需要展示配料表、净含量、生产日期、保质期、生产者信息、产品标准代号等信息。 这一项建议与「仅销售预包装食品备案编号」一并补上。
