两端 UI 重塑方向提案 v0.1

范围：用户端（23 页） + 运营后台（46 视图） · 量级：B 档重塑  · 日期：2026-09-19  · 状态：待你决策
依据：两端现状盘点（机械化扫描） + 用户端/后台对标调研 + 自算 WCAG 对比度实测

一、结论先行

你选的四个痛点里，有三个的根因不是「不好看」，而是「设计系统没被执行」。

两端的 token 文件都写了，后台甚至还专门覆盖了 Element Plus 主题（--el-color-primary:#6e5435）。但到了页面执行层：用户端 130 处裸写十六进制色值、约 20 个页面拿 emoji 当功能图标、状态徽标只有 2 页复用；后台 5 个通用组件全仓 0 引用、每页手写表格。也就是说，规则都在，没人守。

如果这次只是「再画一套更好看的」，半年后必然漂移回今天这个样子 —— 因为漂移的原因一次都没被处理。
重塑的重点 = 建「能被强制执行」的约束 + 补齐缺失的图标体系与组件层；视觉精修是配套，不是主体。

三、三个真缺陷与修复色值

用 WCAG 2.1 公式自算了现有 token（普通文门槛 4.5，大字号 3.0）。结论是：主色系比想象中健康，坏的只是少数几处 —— 所以不需要换主色。

用途现值对比度处置
主文字 / 背景 #6E5435 on #F6F0E5 6.21 达标 不动
按钮字 on 暖棕底 #FFFDF8 on 暖棕 6.93 达标 不动
状态三色 成功 #5B7C3A / 警告 #C44536 / 信息 #4A6FA5 4.71 / 4.86 / 5.03 达标 不动
次文字 #9A8B72 → #796C57 2.93 → 4.51 需改 加深（保色相，明度降 0.118）
金棕当文字用 #C9A876 1.98 禁用 文字位一律改用 #6E5435；金棕只做填充 / 描边 / 图标
等级四色当文字用 见习 #8B7355 4.41 · 首席 #B8892F 3.10（正式/金牌更低） 3.10 ~ 4.41 禁用 见下方说明

为什么「等级色不能用文字色修」

我把四个等级色逐个加深到文字达标，结果是：正式 #896836、金牌 #88692E、首席 #8B6824 —— 四个等级全部塌成同一个深棕，等级就分不出来了。

说明这组色天生只适合承载色块、徽标底色、描边（UI 组件门槛 3.0，它们多数够用），不能承载文字。
⇒ 规则化为：等级信息靠「色块 + 文字标签」表达，不靠彩色文字；确需彩色文字时统一用 #6E5435。这条正好也解决了「低饱和暖色体系里状态色怎么救」的通用难题。

四、两个方向

方向 A · 守品牌，补骨架推荐

视觉语言不动，把缺失的骨架补齐

保留（一律不动）：米色 #F6F0E5 底、暖棕 #6E5435 主文字、楷体、金棕强调 —— 实测 6.21 / 6.93 是健康的。

新建五件事：

  • 统一描边 SVG 图标体系，替换约 20 页 emoji，含菜品图标（把 format.ts 那张 emoji 映射表改成图标组件）
  • 用户端组件层收敛：自绘状态 / 卡片归到现有 8 个组件，清 3 个死组件
  • 后台组件层落地：让那 5 个 0 引用的组件真正被用起来，表格列宽收敛成 3~4 档
  • token 执行纪律：裸写色值纳入 lint 拦截（用户端 130 处一次性归零）
  • 状态规范：空 / 错 / 载 / 禁用四态 + 描边 chip；截单与售罄用「蒙层 + 文案」而非消失（对齐瑞幸做法）

视觉精修：层级靠字重与间距分级、后台密度提供紧凑/宽松切换、数字右对齐等宽。

风险：低。主色不动 ⇒ 已产出的海报、快团团物料、包装全部不返工。
代价：观感提升是「精致」而非「惊艳」，不会一眼变样。

方向 B · 东方新装，气质重塑

连视觉语言一起换

动到主色：背景转暖近白、正文加深，引入材质与版式（宋式留白、低饱和矿物色点缀）。

字体分层：楷体只留大标题与品牌字，正文换可读性更好的无衬线。

收益：气质跳跃明显，品牌辨识度一次性拉起，可直接外延到物料。

风险：高。
① 已产出的海报 / 快团团物料 / 包装需同步返工；
② 楷体分层会改动你此前定的「统一楷体」规范，必须你点头；
③ 工期约为 A 的 1.5~2 倍；
④ 调研称「楷体小字号可读性差」被其自己标注为推断，尚未实测 —— 不宜据此就换字体。

五、我的推荐：A 为主线，B 的「字体分层」单独实测

B 里真正能大幅提升气质的是字体与版式，而不是换掉米 / 棕主色 —— 主色实测是健康的，动它只会牵连返工。所以把 B 里成本最高、收益最不确定的那部分（换主色）砍掉，只留字体 / 版式做小范围真机比对，是性价比最高的路径。

组合收益返工风险
A 全部骨架补齐，漂移问题根治无
+ 字体分层实测气质提升的主要来源，先小样验证可读性再决定铺开可控 仅两三个页面
+ 换主色（建议不做）收益不确定，气质提升并不主要来自这里高 物料全返工

六、本轮明确不做

  • 不动订单 11 态等已验收的业务逻辑
  • 不新增端（后台移动端按「关键路径」做，见待决策项 2）
  • 不做 Figma 协作源文件（交付形态为可预览 HTML 稿 + 代码组件）
  • 不做原创插画 / Logo 美术（需另配图像生成或你提供素材）

七、待你决策（三项）

  1. 方向选择：A（守品牌补骨架）／ B（连主色一起换）／ A + 字体分层实测（我推荐）
  2. 后台移动端：确认按「只做关键路径」（供应商配外卖链接 / 团长看佣金），还是要做成全后台响应式
  3. 楷体使用范围：是否允许「正文改用无衬线、楷体只留标题与品牌字」—— 这条改动的是你之前定的统一规范，必须你点头才动

你定完这三项，我就出第一版设计 token 与关键页面稿；确认后再更新 Spec 与验收基线，最后才落码。
