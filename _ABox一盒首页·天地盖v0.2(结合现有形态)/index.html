动手前先说一件决定工期的事：图片数据早就在端上了，只是一直没被渲染

我原本以为"要上四张菜照"意味着要加表、加字段、改 DTO。回源查完发现不是—— MealDishView 里本来就有 imageUrl，服务端 dishesOfSetMeal 也已经在下发，只是你现在首页的 .dish-row__ico 放的是 iconfont 占位图标， 压根没读这个字段。

⇒ 所以这次改造不动契约、不加表、不改后端，是纯前端渲染改造。 真正的前置工作只有一件：把四张 1:1 俯拍实拍图传上去（后台菜品管理里填 imageUrl）。

格子是怎么对上实物的

  • 数据来源不用改。daily.dishes 现在就是 4 条（服务端按 slot ASC 排好序）， 主食单独在 daily.rice。⇒ 正好 4 格菜 + 1 条通栏饭，不用改契约。
  • 图位就是 imageUrl。现在纵向菜行里那块 112rpx 图位放的是 iconfont 占位图标， 改造后直接读 d.imageUrl——字段已经在响应里了，见页首。
  • 顺序不重排。格子按 dishes 原序从左到右、从上到下填入， 因为那一排是后台编排出来的结果，端上一改就是第二份口径。
  • 盒色不搬。实物的青绿是耗材色，屏幕上仍走品牌米色底 + 暖棕描边， 格子用白底描边代替塑料盒边。
  • 饭 = 底座 = 决策位。实物里饭格最长、最靠底；屏幕上通栏放米饭 + 单价， 紧接其下是份数与预订按钮——整盒的价格落在整盒的底座上，暗示"这是一份，不是四份"。
三栏之间的高度差异可以直观看出：中/右两栏的「概念大卡 + 菜列表」合并成一盒后， 底部按钮比左栏明显上提。

二、格子会不会把"预订按钮"推得更远？（这是改布局最该先算的）

口径：375px 视口（小程序基准 750rpx ⇒ 1rpx = 0.5px），间距/字号取 tokens.scss v2.1 实际值

【现状】一饭四菜卡（纵向 5 行）
  卡片内宽   = 375 − 40(card margin) − 40(card padding) = 295px
  标题       ≈ 15px×1.6 + 10px = 34px
  单行高     = 56px(图标) + 28px(padding $space-3×2) = 84px
  5 行小计   = 420px
  卡总高     = 20 + 34 + 420 + 20 = 494px
  加前一块 hero-card ≈ 177px            ⇒ 现状两段合计 ≈ 671px

【v0.2】天地盖盒
  天盖（压缩后）≈ 98px
  格子内宽   = (295 − 9 gap) / 2 = 143px ⇒ 图位宽 = 143 − 14 = 129px
  图位 1:1   = 高 129px
  单格高     = 7 + 129 + 7 + 22(菜名) + 18(来源) + 7 = 190px
  两排小计   = 190×2 + 9 = 389px
  通栏米饭   ≈ 55px
  盒总高     = 20 + 389 + 55 + 20 = 484px
  加天盖 98px                          ⇒ v0.2 两段合计 ≈ 582px

⇒ 结论：不仅没推远，反而比现状【省约 90px】（≈ iPhone SE 首屏的 13%）
   省下来的主要来自「概念大卡」与「菜卡」去重合并，不是靠压缩图片。
⚠️ 口径声明：以上是按 token 值推算，用于判断方向是否值得做；不是真机实测。 落码后必须上真机核对一次首屏——尤其是图位从 1:1 改成 4:3 时，格子会再省 40px（但"开盖感"会弱一些）， 这个取舍要你拍板，我给不了。

三、落码时必须守的（这五条是有前科的）

  1. 时刻一律从响应取，端上不写死。daily.cutoffAt / deliverAt。 这条你已经踩过一次——原写死 24:00，后台把截单改成别的时刻时横幅还在报 24:00， 而全仓门禁一条都不红。取不到就整行不显示，不要回落任何写死值（回落值就是新的硬编码）。
  2. 格子的顺序 = 服务端的顺序，端上不重排。dishesOfSetMeal 按 slot ASC 下发；格子只是把这条纵列折成两排。不要为了"荤素搭配好看"在端上排序—— 那一排是后台编排出来的结果，端上一改就等于造了第二份编排口径。
  3. ⛔ 小程序端不许写 <ab-icon> 组件。唯一写法是 <text class="abi abi-16">{{ I.chart }}</text>，且 script 段不许出现 I.xxx。有图标锁门禁看着。
  4. ⛔ 格子里的"来自：X"不许变成第三方平台的东西。名称 / 标识 / 链接 / 可跳转物 / 可复制口令， 五项全禁（撞《运营规范》5.10 / 5.20 / 5.15.4，处理是下架）。现在它指向自家溯源页，是安全的， 改布局时别顺手把它改成"去某团点这家"。
  5. 菜数不等于 4 时要有降级，不能空一格占位。 dishesOfSetMeal 目前没有过滤主食槽位（slot=5），它只是恰好种子数据里没编主食； 一旦某天编排了 3 道或 5 道，2×2 就会破版。 ⇒ 建议规则：4 条走 2×2；3 条走上一排 2 + 下一排 1（左对齐）；≥5 条或 <3 条退回现有纵向列表。

四、需要你拍板的三件事

  1. 图位比例：1:1 还是 4:3？1:1 最像实物俯拍（开盖感最强，比现状多约 26px）； 4:3 更省高度（比现状省约 38px）。我倾向 1:1——这个布局的全部价值就在"像打开盒子"， 为此多 26px 值得。
  2. 「来自：X」点下去是跳溯源页，还是原地展开证照（B 稿）？ 现在是跳页。改 B 稿需要 U1 补发证照字段（或点开时现取）， 会动后端；但换来"不打断下单"。
  3. 如果 B 稿成立，独立供应商页的入口是不是就可以删了？ 之前那条线（跳转外卖平台被否后只剩资质文件）其实一直没找到答案； 首页原地展开证照正好是它的解——整条供应商页线就此收口。你说删我就删，不说我不动。
