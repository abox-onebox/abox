## 资质路线：H5 可行性裁定（问答型咨询 · 无代码改动）

用户问：「能不能直接开发成 H5，这样就不需要微信审核？」

**裁定：方向对、结论错。** 微信内 H5 确实不过**小程序**类目与代码审核，
但审核没消失，而是换成三道门，且**支付这道仍在微信手里**。

### 关键证据（微信支付官方文档 · JSAPI 支付开发接入准备）

- 只有 **服务号**、政府或媒体类型公众号才支持申请 JSAPI 支付权限
- **未认证账号无法申请 JSAPI 支付权限**
- 需 **已备案域名**
  ⇒ 微信内收钱 = 必然有「公众号认证审核」这道门；且**微信内置浏览器屏蔽支付宝**，无第二通道。

### H5 净多出的三道门

1. **已认证服务号**（300 元/年 · 1–5 工作日）
2. **域名 ICP 备案 + 境内服务器**（北京约 20 工作日 —— ⚠️ **比小程序备案更慢**，多出域名实名/主机采购/接入商）
3. **业务域名 / JS 接口安全域名 / 网页授权域名**（需 ICP 备案 + HTTPS + 无重定向）

⇒ 结论：**H5 时间不比自营小程序（3–5 周）快，能力全面降级。**

### H5 独有的事后风险（与小程序「过审即稳定」有本质区别）

《微信外部链接内容管理规范》有**过审后的持续拦停权**：
未备案域名 2026 年几乎无法在微信内访问（新增 HSTS 强制加密）；
判定输入含域名历史黑名单 / 关联域名 / IP 信誉；
**同一域名 1 小时内 50 人以上举报、或单日访问量突增 10 倍** → 触发拦截；
申诉需 ICP 备案信息，重复违规可永久屏蔽。
⚠️ 「访问量突增 10 倍」正是**开团当天的正常状态** ⇒ 对盒饭业务是形态自带的触发条件。

### 三条无解的能力缺口（恰好都是命脉）

订单状态推送（仅服务号订阅通知且需逐个授权）· 复购入口（只能收藏链接）·
团长分享形态（纯链接，无卡片无码）。

### uni-app 复用边界（避免误判「顺手就有」）

小程序侧 `uni.login` / `uni.requestPayment` / `uni.getLocation` / 订阅消息
⇒ H5 侧**必须另写**：网页授权 · JSAPI 支付 · JS-SDK 定位 · 无原生推送。

### ⭐ 反向风险（重要）

微信对**小程序餐饮类目有资质前置审查**，对普通 H5 **不做餐饮资质校验**
⇒ 「H5 好上线」不是合规优势，而是**没人替你拦**；H5 上传越快，风险暴露越晚。
123 号令全部实体要求（实体门店 / 三地址一致 / 禁异地代工 / 网店名=招牌名 / 封签）
**在 H5 下一条不减**。

### H5 的正当用途（结论落地）

- ✅ 不带支付的展示页 / 菜单预览 / 加群引导 / 团长招募页 / 兜底承接页 —— **仅需 ICP 备案**
- ❌ 交易主链路 —— 慢且降级，不建议
- ⭐ **ICP 备案应立即启动**（约 20 工作日，纯并行项，与任何形态都不冲突，不占关键路径）
- ⭐ 已被忽略的现成方案：**继续用快团团承接交易**（微信内运行、已持证、不需自过审）
  ⚠️ 但快团团只承平台侧合规，123 号令的**入网餐饮服务提供者**门店与证照要求仍落 ABox 身上

### 前提纠正

用户所说「许可和备案都做完了」大概率 = 《食品经营许可证》经营项目含「预包装食品销售」+ 仅销售预包装食品备案。
