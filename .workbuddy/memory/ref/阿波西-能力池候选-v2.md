## 二、底座洞见（本轮最关键结论）

把上一轮 15 项 + 本轮 16 项 = **31 个能力**摊开，几乎全部只复用 4 个原子底座：

| 底座 | 职责 | 支撑的方向 | 必须一次定死的机制 |
|------|------|-----------|--------------------|
| **记忆体** | 楼维度长期记忆 + **选择性遗忘** | 1/2/3/8/16、上一轮 continuity | 遗忘/清空策略、记忆授权边界 |
| **触发器** | 条件挂起 / 持续监听 / 凑齐才触发 | 4/2/5/6/11 | 超时静默过期、误触发撤回 |
| **路由器** | 匿名 + 订阅 + 可解释 + 可撤回的中继 | 5/7/12/13 + 上一轮全部 relay | 订阅默认关、已读不可撤回、单向渐进亮明 |
| **聚合器** | 个体信号 → 楼维度匿名共识（**不带原话**） | 6/9/10/15 + 上一轮同期声 | 最小样本阈值、k-匿名、原话不出楼 |

**⇒ 定案顺序：先定 4 个底座，再把能力挂上去。**
底座定对 → 后面加一个能力不动其他；底座没定 → 加一个改一片。
这才是"免得后面再修改"的根：**要一次定死的是底座，不是这张清单。**

## 三、代表方向的编排拆解（环节 → 承担者 → 输入 → 输出 → 异常处置）

**A. 条件挂单（#4）**

| 环节 | 承担者 | 输入 | 输出 | 异常处置 |
|------|--------|------|------|----------|
| 提交条件 | 用户 | 自然语言条件 + 阈值 + 有效期 | 结构化挂单 | 条件不可解析 → 复述确认，不臆测 |
| 挂起监听 | 触发器 | 楼内匿名信号流 | 命中计数 | 未凑齐且到期 → 静默过期、不打扰 |
| 凑齐触发 | 触发器 | 计数达阈值 | 一次性询问"现在要联系吗" | 用户不确认 → 不转发、不二次催 |
| 中继撮合 | 路由器 | 双方确认 | 匿名会话通道 | 任一方撤回 → 通道关闭、清缓存 |

**B. 沉默多数唤醒（#6）**

| 环节 | 承担者 | 输入 | 输出 | 异常处置 |
|------|--------|------|------|----------|
| 信号聚类 | 聚合器 | 楼内匿名闲聊/吐槽 | 同向信号簇 | 样本 < 阈值 → 不动作（防噪声当共识） |
| 共识判定 | 聚合器 | 信号簇强度 | "楼里似乎都在想 X" | 强度不足 → 丢弃，不生成 |
| 征询 | 路由器 | 共识摘要 | 询问"要不要我捎个话" | **未获明确确认绝不转发** |
| 回传 ABox | 聚合器 | 已确认的匿名共识 | 楼维度洞察（不含原话） | 回传失败 → 本地留存待重试，不阻塞用户 |

## 四、底座级上线检查（定案时必带）

**可靠性**
- [ ] 4 个底座各自可独立降级，任一挂掉不拖垮其他能力
- [ ] 触发器超时/误触发有静默过期与撤回双保险
- [ ] 聚合器输出在任何路径都不含个体原话与个体 row

**成本**
- [ ] 触发器"持续监听"改为事件驱动，不做轮询常驻（多楼后成本敏感）
- [ ] 记忆体只存楼聚合态，不存全量对话原文
- [ ] 逐楼扩张后按楼核算单楼 AI 调用预算

**权限**
- [ ] 订阅默认关；转发前二次确认不可跳过
- [ ] 跨楼中继仅传楼聚合态，个体数据物理隔离
- [ ] 回传 ABox 单向、匿名、不含原话

**可维护性**
- [ ] 新增能力 = 挂到底座，不改底座本身
- [ ] 每个能力的"可解释中继"文案由统一模板生成
- [ ] 遗忘/清空策略对所有底座一致生效
