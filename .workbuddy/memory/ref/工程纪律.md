# ABox 一盒 · 工程纪律（仓库 / 提交 / 验证 / 高频误用）

> 本档是 `MEMORY.md` §四 / §五 的**展开版**。MEMORY 只留索引；改工具链、提交、写断言前读本档。

## 一、仓库与提交

- Monorepo `abox-onebox/` = **git 仓库根**（`tests/` 与**根文档不入库**，只 `docs/` 镜像入库）；`packages/*` 先 `build:shared`；禁 `@abox/*` paths 指源码（TS6059）。
- **判据只看 `git ls-remote origin refs/heads/main`**；git 用全路径 `…\PortableGit\versions\1.2.0\cmd\git.exe`；提交可直接跑（husky / lint-staged / commitlint 在沙箱内**正常**，无需 `--no-verify`）；**推送需 `dangerouslyDisableSandbox`**。
- 提交拆分：两种**都用过**，别把其中一种当铁律 —— ① **M5-13 / M5-14 形态**：`feat(Mx-y)` **只装代码 + e2e**（`git show --stat` 里**无** `docs/`），紧接着一笔 `chore(baseline)` 装 **全部根文档镜像 + 基线清单本身**；② 更早形态（M5-9 / M5-12）：`feat` 带 `docs/` 镜像，`chore(baseline)` **只留清单本身**，必要时再补一笔 `docs(Mx-y)`。⭐ 真正的不变量只有两条：**同一批内保持一致**（回溯按 `git show --stat` 看哪一笔带 `docs/`）· **`chore(baseline)` 里的清单 HEAD 必须 = 前一笔**（故顺序永远是「先提交代码 → 再跑 `baseline_manifest.py`」，反了就会把上一批的提交号写进清单）。
- ⚠️ **提交后必须复核（#65）**：husky 的 `prettier --write` 会在 **commit 瞬间改写暂存文件** → **门禁验的是「改前」、提交的是「改后」**。对策：① 提交前先 `format:write` ② 提交后对 HEAD 复跑 `gate.mjs all verify` + `verify-manifest.mjs` + `git status --porcelain` 必空 ③ 提交信息文件写到 **ASCII 路径**（`git commit -F` **不吃 `/c/...` 路径**，报 `could not read log file`；`-m` 短句不受影响）。`chore(baseline)` **之前必重跑** `baseline_manifest.py` + `sync-docs.mjs` + `verify-manifest.mjs`。
- ⚠️ **commitlint 有 `body-max-line-length = 100`**（M5-15 实测被拦一次）：`-m` 写的**长段落必被拦**（header 上限同为 100）。
  ⭐ 对策：提交信息写到**纯 ASCII 路径**（`C:\Users\herma\AppData\Local\Temp\*.txt`）用 `git commit -F`，正文**手动按 ≤100 字折行**。⚠️ 必须写 **Windows 形式**（`C:/...`）—— bash 里的 POSIX 形式**即使指向同一文件**（`/c/...`、`/tmp/...`）也会被 git.exe 原样接收而报 `could not read log file`（M5-16 实测：`/tmp/x.txt` 与 `C:/Users/.../Temp/x.txt` 是同一个文件，前者仍失败）
  ⚠️ 项目路径含中文（`ABox小程序`）⇒ 消息文件**不能放在工作区内**；`-F` 吃的是原生 Windows 路径。
  ⭐ 实测：`chore(baseline)` 只暂存 `docs/**` 时，lint-staged 的 `prettier --write` **不会改写镜像**（`docs` 在 `.prettierignore` 里），
  故提交后「根 ↔ 镜像逐字节一致」可稳定通过 —— 但仍要**每次都验**（判据用字节数 + `sha256`）。
- ⚠️ **同一文件的多处改动必须串行** —— 同一轮消息里对**同一文件**并行发多个 Edit，前写会**静默丢失**（#48 已第三次复发）→ 改完**逐条 `grep` 核对**，不靠 Edit 的「成功」回执。
- ⚠️ **`import` 块的改动必须避开「多行 import」的锚点**（M5-11 实测）：把新 import 插在 `import {` 与它的成员行之间，会产出 `import {` 后紧跟另一条 `import` 的**语法错误**（`prettier` 首跑即 `SyntaxError: Identifier expected`）。同族于 #48 —— **多行结构（import 块 / 数组 / 对象字面量）不能作为局部替换的锚点**，要选**完整的单行**作锚点。
- ⚠️ **「上一轮说改过了」不等于磁盘上是新版**（M5-11 实测）：本批开工时三份根文档的改动**声称已做、实际未落盘**（`grep` 关键字符串分别为 0 命中）。⭐ **收尾前一律用 `grep` 抽验关键字符串**（新前缀 / 新字段名 / 新路径），不要相信摘要或记忆。

## 二、文档链路与基线清单

- 链路：改根文档 → `sync-docs.mjs` → `baseline_manifest.py` → **再 `sync-docs.mjs`**（清单本身也是生成物，要镜像）→ `verify-manifest.mjs`。
- ⚠️⚠️ **生成器 ↔ 生成物分叉（M5-15 实测 · 最危险的一类）**：`baseline_manifest.py` 的 `ROLE` / `TESTS`
  是清单表格**描述的真正来源**，而**只有 `tests/` 外的人会看生成物**。上一批把三段描述**只改在生成物里、
  没回迁生成器** ⇒ 生成器**无法复现**当前清单，**下一次重跑会把它们静默回退**成上一批版本；
  因为 `tests/` **不入库**，**没有任何门禁看得见**。
  ⭐ **纪律：`chore(baseline)` 前的重跑必须按「备份 → 跑 → 逐行 diff → 复原」做无损探针**，
  **先看清 diff 再决定是否落盘** —— 直接重跑并提交，等于把一次**文档回退**当成一次「基线刷新」提交进去。
  ⭐ 回迁后验收判据 = **「重跑生成器 ⇒ 与清单逐字节一致」**（连跑两次 `sha256` 相同 = 定点成立）。
  ⭐ 推论：**改了生成物里任何一格描述，都要问「这一格是从哪生成的」**；生成物里的手改 = 下一轮被抹掉。
- ⚠️ **改生成器/补丁脚本的断言必须「双向」**（M5-15 实测翻车一次）：回迁补丁把「锚点行 + `]`」整体替换，
  而**锚点行本身是最后一条登记项**，替换块里忘了写回 ⇒ **静默删掉一条已登记项**（表少一行、零报错）。
  ⭐ **只验「新东西加上了」不够，必须同时验「原有东西还在」**（`src.count(KEEP) == 1`）。
  同族于 `order-state-audit` 首版判据的洞、`check-md-tables` 首版判据的误报 —— **自证不覆盖的失效，就等于没有自证**。
- ⚠️ **改脚本/生成器一律「二进制读写 + 自适应行尾」**（M5-15 实测）：文本模式读 + `newline=""` 写会把 CRLF 文件
  **整体转成 LF**（本次若发生，会让清单里所有字节数集体漂移）。判据同 §二 末条：**字节数 / `sha256`**，`git diff` 看不出来。
- ⚠️ **镜像只用 `sync-docs.mjs`，不要手 `cp`**：它按**版本号**去重（同名同扩展名只留最高版）+ **删掉 `docs/` 里的陈旧镜像**（手 `cp` 只增不减，历史版会永久滞留 → 正是「废弃文档混放」的根因）。
- ⭐ **`docs` 在 `.prettierignore` 里** ⇒ husky 的 `prettier --write` **不会改写镜像**，故「提交后镜像被格式化、清单悄悄过期」这条担心可以排除；但仍要按 §一 复核（`verify-manifest` + 逐份比对）。**判据取字节级 `sha256` 两边比**（M5-14 实测 `diff -q` 对「只差行尾 CRLF」**会**报差异，两者都能用；`sha256` 更直白且不依赖风格）。
- ⚠️ **同一脚本两种规则**：`SCAFFOLD_KEY` 是普通列表注释（**单**花括号）；正文 `body` 是 `""".format()` 模板（**双**花括号 —— 往里写 `` `/{id}/` `` 必须写 `{{id}}`，否则 `KeyError: 'id'`）；`ROLE` 是普通字典，**不需转义**。
- ⚠️⚠️ **往 `body` 里写「正则字面量」必然连踩两次**（M5-11 实测）：`^AB\d{16}$` 先因 `{16}` 被当**位置占位符**报 `IndexError: Replacement index 16 out of range`；把单花括号改成 `{{16}}` 之前若先动 `\d`，`KeyError` 会先冒出来 —— **两次报错指向同一行、原因却不同，很容易只修一个**。⭐ **结论：`body` 里不要出现带花括号的正则，直接用文字描述**（如「`AB` + 16 位数字」）；`\d` 在非 raw 字符串里还会带 `SyntaxWarning`，如需保留正则请写 `\\d`。
- ⚠️ **不加引号的字面花括号同样炸（M5-14 实测，与上一条「正则字面量」同族但更隐蔽）**：㊱ 段正文写了 `` `trace:{buildingId}:{mealDate}` `` → `.format()` 抛 `KeyError: 'buildingId'`；同批另一次是 `` 是 `export {}` `` → `IndexError: Replacement index 0 out of range`。⭐ **判据：`body` 模板里只要出现 `{`，就必须是「模板占位符」或「写成了 `{{`/`}}`」二者之一，没有第三种。**⭐ **可复用排查法**（比逐行肉眼快）：正则 `(?<!\{)\{[A-Za-z_][\w.\[\]]*\}(?!\})` 与 `(?<!\{)\{\}(?!\})` 扫全文，再按三类排除 —— **落在 `body` 模板里的才算**（`ROLE` dict 的值、`#` 注释、`%` 格式串里的花括号都无害；行尾那些 `{n_act}`/`{sc_total}` 是真的占位符）。
- ⚠️⚠️ **`Edit` 返回 success ≠ 磁盘上生效**（M5-14 实测：同一条 `trace:{buildingId}` 的转义改了一次仍报同一个 `KeyError`）。⭐ **改完必须真跑一次脚本**；脚本类改动的验收就是**它的退出码**，不是编辑器的回执。
- ⚠️ **新增根文档必须登 `ROLE`**（否则 `verify-manifest` 覆盖性报「未登记」）；删文档/改版本要去掉旧条目。
- ⚠️⭐ **Markdown 表格「被空行截断」是静默的 —— 已建门禁 `doc:tables` 防复发**（M5-15 实测）：GFM 里**表格遇空行即结束** ⇒「表行 → 空行 → 表行」会让空行之后的表行**退化成带竖线的普通段落**。源文件「看着像表」、渲染出来不是表，而 **prettier / markdownlint / 任何构建工具都不报错**（`docs` 还在 `.prettierignore` 里，连格式门禁都不覆盖）⇒ 落到 **`scripts/check-md-tables.mjs`**，已入 `gate.mjs all`。
  - ⭐⭐ **判据必须排除「两张表相邻」**：`L[k]==='' && L[k-1].startsWith('|') && L[k+1].startsWith('|')` 只是**粗判据**，它会**误报**「表A → 空行 → 表B(表头) → 表B(`|---|`)」这种**完全合法**的形态（接口规范 §6.8 就是），故追加排除：**若 `L[k+2]` 是分隔行则放过**。**误报比漏报更快把人训练成忽略告警** —— 检查器首版正因缺这条而自证失败。
  - ⭐ **最易引入的时机 = 用编辑器/脚本追加表格行**（锚在 `---` 或文末 ⇒ 插入点落在空行之后）。**新表行必须紧贴上一表行。**
  - M5-15 首跑扫出 **5 处存量**：里程碑计划变更记录表 **3 处**（v1.1.4/.5/.7 ⇒ 整表**裂成 4 段**）· 接口规范修订表 **1 处**（「最近修订（M5-14）」整行**粘在 M5-8 行尾** ⇒ 渲染时该行**多出两列**）· 项目目录结构版本表 **1 处**。
- ⚠️ **行尾 CRLF/LF 不影响 git 差异**（`core.autocrlf=true`）：根文档是 CRLF、`docs/` 里的旧镜像有的是 LF，**`diff -q` 会报差异、`git status` 却是干净的**。判据用**字节数 / `sha256`**，别用 `diff`。
- ⚠️ **`SCAFFOLD_KEY`（契约载体白名单）会「整批漏登」而不报错** —— 旧判据（无「（缺失）」行 + 总数一致）对漏登**完全无感**（两边自洽、照样全绿）。**收尾必做机械比对**：`git diff --name-only <上批feat_sha> HEAD` ∩ 已登记路径；若本批新增了控制器 / 服务 / 关键页 / 任务 / 迁移 / 门禁文件而表增量 = 0，即漏登；补登须在批次段说明「补登 + 原因」。
- ⚠️ **种子数据文件不入册**（`seed.ts` 先例 —— 它是数据、不是契约载体）；**一次性探针刻意不进 CI 门禁**（会因 e2e 残留而时红时绿）。

## 三、工具链（pnpm 不可用）

- **pnpm 不可用** → 一切走 `scripts/gate.mjs`（改格式用 `format:write`；`list` 看门禁；⚠️ 手打**不存在的门禁名**只出 `✘ xxx (0ms)` **不报错** → **0ms 门禁先怀疑名字写错**）。
- 跑 node 需 `NODE_PATH=…\node\workspace\node_modules`；⚠️ **ESM 不认 `NODE_PATH`** → 跨目录脚本用 `createRequire` 从仓库根解析。
- bash 报 `dirname: command not found` → 前置 `export PATH="/usr/bin:/bin:/c/…/PortableGit/versions/1.2.0/usr/bin:$PATH"`。
- ⚠️⭐ **`scripts/*.mjs` 完全不在 lint 覆盖内**（M5-15 实测 · 代价一轮 6.6 分钟全量门禁）：`gate` 的 lint 是 `eslint . --ext .ts,.vue`，`format` 的 glob 是 `**/*.{ts,vue,json,md,scss}` —— 两者**都不含 `.mjs`**。于是三支 e2e 脚本的**语法错误**在 `tsc` / `lint` / `format` / `build` 上**全绿**，只在**跑起来那一刻**以 `SyntaxError` 崩掉；而 `e2e:m3` 排在 `all verify` 的**倒数第二位**，前面 20 道全部白跑。
  ⇒ **纪律：改完任何 e2e / 脚本类 `.mjs`，先 `node --check scripts/e2e-mX.mjs`（秒级、零成本）再排门禁。**（本批实际踩的是**重复 `const` 声明** —— 典型的 `no-redeclare`，若在 lint 覆盖内必被拦下。）
- ⚠️ **批量改文件用「一次性原子脚本」**（带期望命中数，`count≠n` 即 `exit(1)`）。
- ⚠️ **沙箱 bulk-delete 守卫**拦 `fs.rmSync`（**>50 文件/轮**即拦，报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`）→ 会**伪装成构建失败**（`nest build` 清 dist 406 文件 / `vite build` 清 dist/assets 125 文件必撞）。对策已内置于 `scripts/gate.mjs`：构建前把 outDir **rename** 到工作区根 `_stale-build/`（每轮先清；bash `rm` 不受垫片约束）；e2e 服务须 `taskkill /PID /T /F`。
- ⚠️ **本机 `http_proxy` 已设**（`http://127.0.0.1:1907`）→ **任何「探本机端口」的脚本都要先假设环境里有代理**：curl 默认尊重 `http_proxy`，于是探 `127.0.0.1` 实际打到代理上、拿回 `502 upstream connect failed` —— **与「服务真挂」同形**（同退出码、同连接失败理由）。对策：探测子进程显式清 `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u all_proxy`。⚠️ 报错信息相同 **≠** 根因相同。

## 四、e2e / 断言纪律

- ⚠️ **取数层级**：`code` 在 `.body` 上、**不在** `.body.data` 里（写成 `data?.code === 0` **恒假**，且诊断行还打印「看似正常」的数据）· **断言条数按运行输出计**（静态 `grep -c 'assert('` 会漏）。
- ⚠️ **两套 e2e 不能并发跑** —— 端口 / sqlite 争用会让后跑者**静默不出汇总行**（用 `grep '^通过'` 抓条数时表现为「无输出」而非失败，极易误判成「套件崩了」）。
- ⚠️ **追加整节必须插在 `await stopApiServer()` 之前** —— 否则夹具（直连 SQLite）全过、第一条 HTTP 才 `fetch failed`，且日志无服务端痕迹（极易误判为「服务崩了」）。
- ⚠️ **直接跑 `e2e-mX.mjs` 必须复刻 gate 的 env**（含 `E2E_PORT`）且**必须先 `seed`** —— 否则会以 `TypeError: Provided value cannot be bound to SQLite parameter` 崩在中途（看起来像套件坏了）。
- ⚠️ **e2e 用 sqlite 测不出真并发**（单连接同步驱动把两次事务**串行化**）→ 真有并发语义的断言必须**如实标注「本测不具鉴别力」**并转真机 MySQL。
- ⚠️ **`gate.mjs` 成功时丢弃子进程 stdout**；要条数须用 node 包装器复刻其 env。
- ⚠️ **单测里照抄声明表的断言会「锁死」一个错误** → **删声明时必须搜 `test/`**（并改成双向锁定：正向证一步到位 + 反向**明确断言旧边不成立**）。
- ⚠️ **写库断言前先确认列在哪张表**（`ab_order` **没有** `actual_at`，只有 `ab_delivery_record` 有）。
- ⭐⭐ **「黑盒机械对账」的两条硬约束**（M5-12 · `e2e-m3` §36）：① **出厂 / 基准口径必须在断言里写死复刻，刻意不 `import` 服务端常量** —— 否则就是「**拿实现验实现**」，实现改错了断言跟着一起错、**两边互相担保而恒绿**；只有**两条独立路径**才能互相证伪。结构性派生只保证「同一份源」，**不保证「外部看到的就是它」**。② **必须有「反证」组** —— 只验正例会漏掉「它压根没读那份源」这种情况（§36 的反证 = 4 个不可配项在配置全被改掉时仍为出厂值）。
- ⭐ **双向断言优于单向**：「偏离基准的集合 **恰好等于** 被改动的键对应集合」（少了 = 没接上；**多了 = 存在第二个写入点**）；「某值在输出里**不留任何一行**」用显式 `null` 表达并写进断言。
- ⭐ **节首归一 + 节末复原并断言复原**（凡本节**真改过共享状态**的都要做）：不还原会把污染留给后续节与重跑，症状是**「其它节偶发红」**，因果关系极难建立。

## 五、高频误用红线（每批过一遍）

- 金额出参**一律整数分**（`Fen` 结尾）；**扩展错误码必须回写《接口规范》§九**；**静态路由须声明在参数路由之前**；**两级白名单**（类级含 `operator`，写 / 资金动作收窄）。
- **白名单与菜单同源**，不许单边漂移；⚠️ 看板族**含** `viewer`、资金族**不含**，方向相反要逐个确认。
- **派生值不落库**（唯一例外：生产计划**生成即冻结**）；**错误码语义相近 ≠ 可复用**（`40002`/`40015` · `40016`/`40017` · `30016`/`30017`/`30018`）。

## C9. ⭐ 根目录 `_` 前缀 = 「不进冻结基线、不进门禁」的既定通道（2026-09-21 查证）

新增工作文档（前置包 / 登记册 / 执行清单）时，**根目录下以 `_` 开头的 `.md`/`.html` 会被三道机械检查同时跳过**，
故它是「既要写在项目里、又不能扰动基线」的**唯一既定通道**。机械依据（三处，缺一不可）：

- `tests/tools/verify-manifest.mjs:84` —— 覆盖性判据是 `!n.startsWith('_')` ⇒ 不登记也**不算未登记**（否则 exit 1）。
- `tests/baseline_manifest.py:798` —— 生成器 `if name.startswith("_"): continue` ⇒ **不写进清单**。
- `abox-onebox/scripts/check-md-tables.mjs:38` —— **刻意只读仓库内 `docs/`**，不读工作区根 ⇒ 表格形态不进门禁。
- ⭐ `abox-onebox/scripts/sync-docs.mjs:56-59` —— 镜像只捞**文件名以 `ABox一盒` 开头**的 `.md`/`.html`
  ⇒ 以 `_` 开头者**天然不匹配**。⚠️ **注意归因**：这里**不是**显式 `startsWith('_')` 判据，
  而是「`ABox一盒` 前缀」这条**另外的规则**把它排除在外 —— 两条规则**碰巧**都拦住了 `_` 文件。
  ⇒ 推论（易错）：若把文件命名为 `ABox一盒XXX.md`（**不带 `_`**），它会**被镜像进 `docs/`**，
  从而**一并进入 `doc:tables` 的扫描范围**；且 sync-docs 会**按版本号自动淘汰低版本**
  （同名更高版本出现时，低版本被移出 `docs/`）—— 所以「带 `_`」与「走镜像」是**两条互斥的路**，别混用。


实测：`_ABox一盒第三方专家测试前置包` 当日经 v1.0（24791 B）→ v1.1（27946 B）→ **v1.2（28707 B）**，每次改后复跑 `verify-manifest` 均为 **315/315 · 未登记 0 · exit 0**；新增 `_ABox一盒已知项与预期行为清单v1.0.md`、`_README-第三方测试起始说明.md`、`_ABox一盒第三方测试快照v1.0.zip` 同样零影响。
⚠️ **反面**：根目录**不带** `_` 的新文档**必须**登进 `ROLE`，否则 `verify-manifest` 立刻报「未登记」→ exit 1。
⚠️ 判据是**文件名首字符**，不是「放在哪」——`archive/` 里的文件照样被扫（`scan(ARCHIVE, "archive/")`）。


## C10. ⚠️ EOL 结论会过期 —— 每次动手前重新探测，别把「上一轮统一成 CRLF」当事实

本批更新《悬而未决登记册》时，延续上一轮的结论「该文件是 CRLF」，把 `final.count('\r\n') == final.count('\n')`
写进了收尾断言，结果**触发失败**：该文件**当时实为纯 LF**（CRLF=0 · 裸LF=146）。数据写入是对的，**错的是检查器**。

- **教训一：EOL 不是文件的固有属性，是会变的。** 上一轮刚「统一为 CRLF」，下一轮读到就是 LF —— 中间可能被任何一次
  `Edit` / 格式化 / `core.autocrlf` 往返改掉。⇒ **每次动手前现场探测**（`count('\r\n')` 与 `count('\n')` 现算），
  **不要沿用上一轮的结论**，也不要把 EOL 断言硬编码成某一种。
- **教训二：检查器的判据必须由「输入实际形态」驱动，而不是由「我以为的形态」驱动。** 断言写成
  `if 我以为是CRLF: 那么必须全 CRLF` ⇒ 一旦前提错了，**写入正确也会报错**（本次即此）。
  正确写法：先探测 `eol`，再断言「**文件内部一致**」（要么 0 处非本位 EOL，要么全部一致），而不是断言「必须是 CRLF」。
- ⭐ **与 C7 同源**：自证的负控只能证明「锚点错会拒绝」，**证不了「断言的前提对不对」**。
  前提性错误的典型信号 = **写入成功但断言失败** —— 此时**先怀疑断言**，别急着回滚数据。
- ⚠️ **2026-09-25 再证（同一份仓库里两种 EOL 并存）**：`tests/baseline_manifest.py` 是**纯 CRLF**
  （1008 CRLF / 1008 LF），而同轮正在写的 `_tmp/gatepipe/*.mjs` 是 **LF** —— **同一个仓库里两种都有**。
  补丁脚本第一版按「这份是 LF」构造锚点 ⇒ **命中 0 处**（被命中数断言拦下、**0 字节写盘**）。
  ⇒ 正确姿势三步：**① 读原文现场探测 EOL → ② 用探测值构造锚点与插入行 → ③ 写盘后断言「EOL 纯度」**
  （本轮插入 4 行：1008/1008 → 1012/1012，且 CRLF 数仍等于 LF 数）。
- ⭐ **不要把「刚才探测到 CRLF」记成文件的属性** —— 它只对**这一次读取**成立；下轮**重新探测**。

## C15. ⚠️ 从 Markdown 表格里抽字段：**行尾的 ` |` 会被一并吞进内容**（2026-09-23 实测）

用 `\|\s*\*\*字段名\*\*\s*\|(.*?)(?=\n\||\n\n|\Z)` 抽表格单元格时，
**当前行结尾的那个 ` |` 同样落在 `.*?` 的捕获范围内** —— 因为 `\n\|` 前瞻匹配的是**下一行**的行首竖线。
⇒ 抽出的每格都多带一个竖线；若随后按规范把 `|` 转义成 `\|`，整行就多出 6 个转义竖线，
表格渲染出多余的 `|`，而**任何「字段是否非空」的检查都不会报错**（内容确实非空）。

**正解**：`v.strip()` 后 **先摘掉行尾竖线**（`if v.endswith("|"): v = v[:-1].rstrip()`），**再**转义剩余的 `|`。
**配套负控**：校验必须断言「行内不含 `\|`」且「每行 `|` 计数 == 列数 + 1」。只数「格数够不够」抓不到这个。

⚠️ **同族第 N 次（本轮连踩 4 次）：探针字符串必须从产物里复制，不能凭印象手打。**
本轮 4 处「红」全是探针写错、不是产物有错：① 区间写法 `` `SC-U-01`…`U-13` `` 被漏算 ⇒ 虚报「执行顺序只覆盖 14/110」；

③ 探针写「12 个批次」而产物根本没有这个串；④ 正则写 `不符记 \*\*P[012]`，而产物是 `**不符记 P1**`（`**` 在「不符记」**前**）。
⇒ 铁律：**写完探针，先在产物里 grep 一次它实际长什么样**；探针不命中，**先怀疑探针**。

## C17. ⚠️ 批量脚本的两个「自身缺陷」，会把正确改动判成失败（2026-09-23 实测）

## C18. ⚠️ 原子补丁的「旧串已消失」自证：不能写 `old in text`（2026-09-25 实测）

```python
want = files[p].count(old) - exp + new.count(old) * exp     # exp = 期望命中数
got  = text.count(old)
assert got == want, '旧串剩余 %d 次，按构造应为 %d 次' % (got, want)
```
（顺带：`py_compile` 会在**同目录**留下 `__pycache__/<tmp>.cpython-*.pyc` ⇒ 用临时副本做语法预检时
记得连 `__pycache__` 一起清掉，别污染工具目录。）

- **第②层的教训**：`e2e:m3` 一条断言**恒红 17 天无人发现**（09-15 写的 D52「operator 菜单不含 `/system/*`」，
  被 10-02 引入的 `OPERATOR_EXTRA_MENUS=/system/queue` 撞翻）。
  ⇒ **动后端 / 角色 / 菜单后必须补跑 `verify`**（约 2.5 分钟）。
- **第③层的教训（2026-10-03 实测）**：资质墙两个新端点只过了 `typecheck` + 门禁，
  **一次真实请求都没发过**。补测才发现探针按猜的字段名写（`data.suppliers`）全落空，
  真实结构是 `data.serving` / `data.inactive` ⇒ **探针字符串必须从产物里复制，不能凭印象手打**。
- 第③层最低要求：每个新端点逐个实调；改了行为的旧端点跑前后对照；**把真实返回值贴出来**，不写「应该没问题」。
- **验证落库**：接口出参往往不含新字段（如取消理由），只看响应永远发现不了「没写进去」
  ⇒ 必须**直查库**（e2e 环境用 `node:sqlite` 的 `DatabaseSync`）。
- ⭐ **e2e 条数现有机械下限**（10-07 α 批次）：三份 e2e 收尾 `results.length === 0` 即 exit 1；
  `gate.mjs` 的 `EXPECT_MIN = { 'e2e:m1':114, 'e2e:m2':150, 'e2e:m3':1335 }` 解析「通过 X/Y」
  判规模缩水 ⇒ **删断言会让门禁红**，阈值只许上升（要降必须改 `gate.mjs` 并写明理由）。
  ⚠️ 口径陷阱：`X/Y` 里 **Y 是总数** —— 缩水是 `1300/1300`，**不是** `1300/1335`
  （后者是 35 条失败，规模达标，由脚本 exit code 管）。
- ⭐ **新增门禁必须进别名或登记豁免**（否则 `gate:parity` 红）：不在任何别名里的门禁
  须写进 `check-gate-parity.mjs` 的 `CI_EXEMPT` 并写明理由；现存 3 道豁免 =
  `format:write`（写命令）/ `seed:demo`（与 e2e 种子互斥）/ `design:docs`（语料不在仓库）。
  豁免项若已不在 `GATES` 中会被判「腐烂」。

## D3. ⭐ 探针直开 sqlite 的两个必踩坑
1. **`database is locked`**：API 服务持有同一 sqlite 连接，刚发生过写（**尤其 mock 支付后**）
   会撞锁，探针直接崩。修法 = `PRAGMA busy_timeout = 8000` + 写操作带退避重试（同步忙等 8 次）。
   ⇒ **这是探针缺陷不是产品缺陷**，别急着回滚产物。
2. `.mjs` 是纯 JS，**不能写 TS 类型注解**（`let x: T` / `as T`）⇒ `node --check` 秒级抓到。

## D5. ⭐ 取消统计的口径（2026-10-04 功能，易记错）
- **核心字段是 `cancel_source` 不是 `cancel_reason`**：三条路径（用户自助 `user` /
  截单清未支付 `system` / 团长代退 `leader`）过去都只置 `cancelled`，不分层会把
  「忘付款被系统清掉」混进「用户主动放弃」⇒ **统计必须先按来源分层**。

## D6. ⚠️ 「错误响应恒 HTTP 200」这条老说法**不精确**（2026-10-29 生产实测校准）
- 一直记的是「错误响应恒 HTTP 200 + `body.code`」，照它写文档/清单会害人 ——
  实测三种情况分得清清楚楚：

  | 情况 | HTTP | `body.code` |
  |---|---|---|
  | 业务成功 | 200 | `0` |
  | **业务**失败（参数错 / 状态不符 / 超限…） | **200** | 非 0 |
  | **未登录 / token 无效** | **401** | `10002` |
  | 登录时账号密码错 | 200 | `20005`（连续 5 次锁 900s） |

- ⇒ 正确表述：**判成败一律看 `body.code`**；「恒 200」只适用于**业务**错误。
  响应外层统一 `{code, message, data, requestId, timestamp}`。
- ⇒ 顺出的经验：**探测路由是否存在，用「不带 token 打」** —— 返回 **401** 即证明
  「路由存在且受鉴权保护」，返回 **404** 才是路径写错。比 grep 启动日志更硬，
  也不需要登录。（本次用这条实测校准了 8 条新路由。）
