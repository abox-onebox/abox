### 9.1 ⭐⭐ 链路口径：为什么是 8080 不是 8081

`443 → 127.0.0.1:8080(admin 容器 nginx) → api:3000`。
**只有 `apps/admin-web/nginx.conf:125` 有 `location /wecom/ → api:3000`**；
`apps/miniprogram/nginx.conf`（h5 / 8081）没有该块且 `location /` 有 Cookie 闸门
⇒ 走 8081 必 401。`api:3000` 不对宿主机暴露，别试图给 3000 开端口 / 改 compose。
宿主配置固化在 `abox-onebox/deploy/nginx/abox-443.conf`（与线上 sha256 一致）。

### 9.2 ⭐⭐ 三处静默缺陷（GET 握手能过、POST 消息永远收不到）

2026-11-10 生产实测挖出，缺一不可，**只修 443 是半成品**：

| # | 缺陷 | 现象 |
|---|---|---|
| ① | `forRoutes('*')` 展开只覆盖 `/api/v1/*`，够不到被 `exclude` 的裸路径 | `req.rawBody` 恒 undefined |
| ② | `request-body.middleware` 只注册 json/urlencoded，企微发 XML | 两个 parser 都 skip，verify 不触发 |
| ③ | `WecomKbService.xmlTag()` **不剥 CDATA** | 拿 `<![CDATA[…]]>` 算 SHA1 ⇒ 签名恒不符 / 解密失败 / 指令解析全废 |

第 ③ 条最隐蔽：企微官方《加解密方案说明》示例里 `<Encrypt>`、`<FromUserName>`、
`<Content>` 全是 CDATA，三类故障**都只打一条 WARN、不报 500**，极易误判成「企微没推消息」。
修法：新增 `wecom-raw-body.middleware.ts`（全局 `app.use` + 内部精确判路径，
`rawParser({type:()=>true})` 挂 rawBody；GET/HEAD/OPTIONS 直接 next 保握手）；
`xmlTag` 抽成导出纯函数 `wecomXmlTag` 统一剥 CDATA。
⛔ **不要改 `request-body.middleware.ts`**：它是 2026-10-27「GET 带体打成 10001」事故收口件，
全局 300+ 端点，为 XML 改作用域等于重开事故面。

  造成假绿。
- ⚠️ **「空日志」不能当成功**：正样本无异常属消极证据。补积极证据：合法签名 +

- ⚠️ **探针复用产物实现**：单测别自己复刻 `xmlTag` 正则（初版 6 红都是探针错）。

## 十一、问参数要「说人话」：94 个必填参数全部补上中文提示（`39f37e2`）

### 起因

137 个端点里 49 个带必填参数（合计 94 个），**17 个在目录里 hint 为空** ——
机器人只会问「还需要：role」「还需要：opCode」，用户根本不知道填什么。

### ⚠️ 三个根因，没有一个是「忘了写注释」（凭印象改会改错地方）

| # | 根因 | 规模 |
|---|---|---|
| ① | 描述写成模板字符串 `` `角色：${ROLE_HINT}` `` —— **为和 `@IsIn` 共用一份取值、不重复维护**，而生成器只认单引号字面量 | 20 处 |
| ② | 描述跨行（`description:` 换行、值在下一行），生成器按单行匹配 | 167 处写法里的 DTO 部分 |
| ③ | `@IsIn(ADMIN_ROLES)` 传**常量名**（非字面量数组）+ **全仓 0 处 `@ApiParam`** ⇒ 枚举取值与路径参数没有来源 | 58 处 / 7 个路径参数 |

修法全在 `gen-wecom-catalog.mjs`（**不重复维护描述，仍是读 DTO/注解真源**）：
- 认三种引号（`'`、`"`、`` ` ``）+ 跨行取值（`awaitDesc` 状态）+ 常量内联；
- 常量索引支持 `ARR.join('sep')` 与 `Object.keys(对象字面量)`（`ADMIN_ROLES = Object.keys(ROLE_MENUS)` 两层间接）；
- 新增 `parseApiParams()` 解析 `@ApiParam`（`sig` 从方法签名行开始，**不含装饰器**，得单独扫上面一段）；
- 给 7 个路径参数补 `@ApiParam`、给 `wecom-binding.dto.ts` 补 `@ApiProperty`（顺带补了 swagger）。

### ⭐⭐ 对象键解析必须**按行**匹配行首 `标识符:`

逐字符扫会把**值里的字符串也当成键** —— 实测 `ROLE_MENUS` 的值是菜单路径数组，
逐字符版把 `/system/queue` 等全收进来，`role` 的提示变成
「super_admin / admin / operator / **/system/** / finance …」。按行 + 冒号结尾才对。

### ⭐ 截断要「语义完整」，不能硬截

- 取值清单超 6 项 → 列前 6 个 + `等 N 项`。硬截到 140 会切成 `…manual_a` 这种半句话，
  用户以为是显示问题。

  重复的字数会把真正需要的内容挤出去（判据：前 3 个取值都已出现在描述里）。
- 问句 `askNext` 的截断 100 → **160**（目录 hint 上限 140，160 保证整段都能显示）。

## 十二、出参说人话：执行完不再吐截断 JSON（`52347d5` + 路径参数修复）

### 一、通用摘要原来只认 7 个字段名

`summarizeResult` 以前只认 `id/orderNo/status/totalCount/count/ok/tier`，
认不出就 `JSON.stringify(...).slice(0,600)`。137 个端点里 **64 个只读**，几乎全对不上。

现在按**返回形态**分三路（`result-summary.ts`）：
- ① 分页信封 `PageResult{list,page,pageSize,total,hasMore}`（全仓 22 个 service 用它）；
- ② 数组；③ 单个对象。

⚠️ **`total` 并非总有**：线上实测 `deliveries` / `op-blocklist` / `schedule` /
`system-roles` 四个端点**只有 `list`**。判据必须是「`list` 是数组」，
`total` 取不到就用本页条数 —— 否则掉进单对象分支，吐「后台返回了 N 个字段」。

### 二、⛔⛔ 白名单，绝不「有什么印什么」

用户列表行里有 **`passwordHash`**！泛印等于把密码哈希发到企微群（永久留痕）。
`result-fmt.ts` 的 `FIELD_SPECS` 是**唯一**字段来源，认不出时只报
「后台返回了 N 个字段」，**一个原值都不 dump**。单测盯着这一条。

配套：同义键折叠（`status` → 优先 `statusText`/`statusLabel`）、
同值去重（`realName`==`nickname` 只念一次）、数组只念条数、
金额 `*Fen` → `¥x,xxx.xx`、**取不到就跳过，绝不补 0**。

### 三、⭐ 绝不能读 `dishes`：响应拦截器有兼容别名层

`common/interceptors/response.interceptor.ts` 会递归给旧的餐饮字段名做**镜像**：
`items→dishes`、`itemName→dishName`、`itemCount→dishCount`、`mainItemName→mainDishName` …
所以出参里 `dishes` 常常只是 `items` 的副本。
实测 `GET /admin/wecom-kb/ops` 返回 `{total, items, dishes}` 且 **items === dishes**，
我第一版把 `dishes` 当「菜品词表」念出了「菜品 137 条」—— 假数。
⇒ **摘要只读新名**；任何 `dish*` 键都当别名，不当数据。

### 四、8 个结构化端点写定向摘要（`result-directed.ts`）

待办 / 财务总览 / 订单详情 / 套餐矩阵 / 楼栋总览 / 队列 / 打包任务 / 端点目录。
通用三路对嵌套对象只会说「后台返回了 N 个字段」，而这 8 个恰好是每天要用的。

拿真实响应校准出来的几条口径：
- **待办只念 count>0 的**（后台固定返回 4 项，0 的念出来是噪音）；
  计数**不写量词**（「5 件」会把 5 个楼群说成 5 件单）。
- **财务总览**：`range.startDate` 是 `end − (days−1)`，近 7 日 = 10-27 ~ 11-02（**对的**）；
  `warnings` 必须逐条转述（毛利 90.7% 这种数只有配着它才不会被误读）。
- **订单详情**：只念「第一个未完成节点」和 `actions.refundableFen` / `adjustBlockReason`，
  全念一遍没人看。
- **队列**：`failed>0` 必须带 ⚠️。
- **套餐矩阵**：`dateCount × groupCount = cellCount` 的口径要念出来，
  再点名「有空楼」的楼群（一格没排就等于开不了团）。

### 五、⭐⭐ 详情类只读端点的路径参数根本没进目录（严重，静默给错数据）

线上实测：问「订单详情」→ 机器人直接执行 → **返回 98 条订单列表**。
根因：`gen-wecom-catalog.mjs` 的路径参数**只扫方法签名里的 `@Param('x')`**，
而 8 个详情类 GET（`/admin/orders/:orderNo`、`/admin/users/:id` …）用的是别的写法
⇒ `params` 是**空数组** ⇒ 空参按 `/admin/orders/` 打过去，**命中列表路由**。
标题写着「订单详情」，数据是整张列表，**不报错**。

修法两条（缺一不可）：
1. **生成器**：路径参数取 `路由模板里的 :name` ∪ `@Param('x')` 的**并集**
   —— URL 里明明写着必须有一段，这是权威来源。带路径参数的端点 6 → **52**。
   提示文案：`@ApiParam` 优先，否则查 `PATH_HINT`（`orderNo`/`id`/`proofId`/`userId`/`opCode`/`task`/`role`）。
   ⚠️ 别给 8 个 `:id` 各补一遍 `@ApiParam` —— 同一句话抄 8 遍，改一处要改 8 处。
2. **聊天层**：只读端点**先问齐必填再查**（以前一律空参直接查），
   问齐后**直接执行**、不再要「回 1」（只读没有副作用，不该多一次确认）。

另外 `execCatalog` 本来就有「缺必填 → 422」的闸，所以参数进目录后空参也打不出去了。

## 十三、AI 编排节点脚本的两个坑（2026-11-03 落地 N/O 时实测）

### 13.1 ⭐⭐ `LLM_EMPTY` 多半是假象：其实是「首 token 还没吐出来就被 abort」
- 报错长这样：`LLM 解读失败：LLM_TIMEOUT(20000ms): LLM_EMPTY: 模型返回为空`。
- 读法：`cloud-llm.mjs` 在 `ac.abort()` 之后若 `answer` 仍为空，先抛 `LLM_EMPTY`，
  再被外层 `catch` 包成 `LLM_TIMEOUT`。**所以「TIMEOUT + EMPTY 同时出现」= 20 秒内一个 token 都没收到**，
  不是模型拒答、不是内容违规、也不是 prompt 写错。
- 实测：同一份输入、同一 system prompt，**20s 恒空，45s 正常出稿**（可复现）。
  长输出 prompt（约 1100 字）更容易踩，短 prompt 偶发。
- 现行取值：N（团长健康度）`45000`、O（经营健康度）`40000`、M（流失召回）`20000`；
  service 侧 `spawn` 超时统一 **90s**，故脚本内 <45s 都安全。
- ⇒ 纪律：**判 LLM 失败先分「一个 token 都没吐」还是「吐了一半断掉」**，前者先加超时，
  别急着改 prompt / 换模型。

### 13.2 ⭐ 意图正则的顺序本身是判据（N 必须排在 O 前面）
- 「团长健康度」同时命中 N（`团长健康度|团长流失|…`）与 O（`经营健康度|健康分|健康度`）。
  若先判 O，团长问题会被全局经营分截走，**静默给错答案**。
- ⇒ 规矩：**宽泛词（健康度）的分支一律排在带限定词（团长…）的分支之后**；
  新增意图时必须先跑 node 自证「A 是否命中本该归 B 的句子」，再决定插入位置。
  同批已自证：M 的「留存预警」不吃 N（`团长留存预警` 不命中 M）。
