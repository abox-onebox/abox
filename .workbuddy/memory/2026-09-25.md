## 一、系统性真缺陷：`sticky` 侧栏底部**够不到**（跨 5~6 件）

**症状**（由 F3 探针 4 条红追出）：侧栏（`.side`）高于视口可用高度时，`position: sticky` 会让它
**底部被钉住不动** —— 滚页面也带不上来，必须滚到**整页最底**（那刻 sticky 才脱离）才够得到。

**实测（`_dbg_side.mjs` · 1440 宽）**：R1 末控件底 928 · 经营驾驶舱 952 · S2 990 · **G1 1646** ·
**G2 1310** · **F3 1631**；1440×1080 下 G1/G2/F3 **仍够不到**。

**修法（共享 `_tmp/p0/_shared/shell.css` · 一处改、六件受益）**：
```css
.side { position: sticky; top: 62px;
        max-height: calc(100vh - 62px - var(--sp-3));   /* 62px = .top 实际高度 */
        overflow-y: auto; overscroll-behavior: contain; }
```
窄屏媒体查询里**必须解除**（`position: static; max-height: none; overflow-y: visible`），
否则手机上出现一个 **1/4 屏高的小滚动盒**。

**E3 内容工厂**是**手写外壳**（`.fc-side`，不引 shell.css）⇒ 不共享此修；它原本已有
`max-height + overflow:auto`（免疫），但少了底部呼吸位（见 §五）。

## 七、本轮新增/沿用的纪律（值得带进下一个工具）

1. **改共享源件前先查「谁追踪了它」** —— 引用 ≠ 追踪。要同时查 `build.py` 的 `shared_files`
   与 `selftest.py` 的 `shared_files`（两处都要），且**手写版 selftest 是独立第三处**。
2. **探针断言「变化量（集合差）」而非「绝对值」**，但要求变化**恰好等于**目标项、其余一行不动
   —— 这是「不受前置状态影响」与「不放走真缺陷」的唯一同时满足写法。
3. **改判据之前先取数**，并且**取数脚本要逐步复刻完整前置序列** ——
   简化复刻会得出相反结论（本轮我第一支取数脚本就得出「⑩ 不会红」，与探针相反）。
4. **自证口径不能比实质判据严**（`top == sticky` vs「不高于 ∨ 无可滚区间」）——
   过严的自证会把达标产物判红，也是假红来源。
5. 「0 样本 / 本就不适用」必须**正面断言**，不留静默跳过。

## 十一、⭐ 垫片第一版**漏了「缺省 stdio 即 pipe」** ⇒ `gate:parity` 独红
