### 关键设计裁定（可复用判据）
- **探针必须分级**：liveness（要不要重启我 · **不检依赖**）/ readiness（要不要给我流量 · **检依赖**）。混用两种后果都是灾难：liveness 检 DB → DB 一抖就**重启风暴**（重启治不好 DB）；只留不检依赖的版本 → **摘不掉流量**。
- **readiness 检「队列消费者齐不齐」而不是「Redis 通不通」** —— 连通性在**启动期已 fail-closed 验过**（连不上即拒绝启动）；「消费者没注册上」是**启动期验不到、失败后完全静默**的一类故障（入队照常成功、`GET /admin/queue` 计数照常显示、任务永远无人消费）。
- ⚠️ **必须显式传 503**：`ErrorCode.SERVICE_UNAVAILABLE=90002` **不在** `HTTP_STATUS_OVERRIDE` 表里，而本项目业务失败默认 HTTP 200 → 不显式传就退化成 200，**编排器只看状态码 → 「不可用」被判成健康**。
- **免鉴权探针 = 公网可见端点** → 出参按「会被人看见」设计：失败原因（主机/端口/连接串）**只进服务端日志**，HTTP 给固定文案。
- **`/health` 出参契约不可改**（三套件 `waitHealthy()` 依赖 `HTTP 200 && code===0`）→ 新增能力一律走新端点。
- **优雅关闭的验收方式本身有坑**：Windows 上 `process.kill(pid,'SIGTERM')` 走 `TerminateProcess`、handler **不跑** → 改用进程内 `process.emit('SIGTERM')` + **跨进程子脚本**在钩子执行瞬间 `writeSync(1,…)` 落标记（**「进程退出了」不算证据，强杀也会退出**）。
- 容器 **exec 形式 CMD** 是优雅关闭的**前提**：`sh -c` 会让 PID 1 变成 sh，信号到不了 node。

### ⭐⭐ #49 的修法（值得记住的结构性教训）
- **根因不是笔误，是「装饰器是静态元数据」**：`@Cron()` 的参数在模块加载时求值一次即成静态元数据 → 后台改配置**永远影响不到它**。所以「让 cron 去读配置」也解不开「配置 / 声明表 / 锚点各写一遍」的结构 → 正解是**一处声明、两处派生**：`DEFAULT_TIMELINE`（`common/utils/order-timeline.ts`）为唯一真相，`TASK_SCHEDULES[*].cron` 与下单窗口锚点（`time.ts` 的 `*AtOf`）都改成它的**派生值**
- ⭐ **必须热重载**：只在启动时读一次会造出**半生效** —— 配置改了 → 下单窗口**立即**变、截单跑批仍按老时刻跑，**两处都不报错**（比不接线更难查）。`setCurrentTimeline()` 带变更通知，`tasks/schedule.registrar.ts` 订阅后重载
- ⭐ **读表失败绝不回落默认时间轴**（`BizConfigService.loadedOk`）—— 一次 DB 抖动就会把运营配的时刻**静默改回出厂值**
- ⭐ **`24:00` 是模型缺的一个值，不是笔误**：截单口径的原生表达就是 `T-1 24:00`（= T 日 0 点），旧校验只收 `00:00`–`23:59` → 种子只能写 `23:59` 近似 → 与按 `00:00` 跑的 cron **差 1 分钟且到处不报错**。种子据此更正为 `24:00`
- ⭐⭐ **新增「跨键自洽校验」**：逐项合法 ≠ 组合有意义 —— 开团晚于截单 → 下单窗口是**空区间**（谁都下不了单），而每项单独校验都过、系统照跑、**无任何报错**；这类矛盾**只有同时看两个键**才看得出来
- ⭐⭐ **`dateKind` 也必须派生**：`cutoff` 是唯一会因配置改变「动哪一天」的任务（`24:00` 落 T 日 / `23:30` 落 T-1 日）；写死 `today` = 「把截单改到 23:30」变成**静默锁错日期**（跑批「成功」、当天订单一张都没锁）
- ⭐ **最危险的失败形态是「任务静默不跑」**（不再有装饰器报错兜底，而 e2e 全走补跑接口 → **发现不了**）→ 三道防线：逐名 `doesExist`（缺则**拒绝启动**）· 启动横幅 · S1 下发 **`registeredCron`**（出厂 `cron` 与实际注册值的差异即「配置覆写」的证据）

### ⚠️ 单测当场抓出的一个错（「把常量换成读配置」的经典陷阱）
- `cutoffAtOf()` 原写「以 **T 日** 为基准 + 0 点」，改造时直接换成「T 日 + `timeline.cutoff.hour`」—— 默认值 `24` 下**结果差一整天**（`T 日 24:00` = T+1 日 0 点）。**等同性只在 `hour === 24` 时成立**（`T-1 24:00 ≡ T 00:00`，但 `T-1 23:30 ≠ T 23:30`）→ 基准日必须取 **T-1**
- ⚠️ 若没有 `time-anchor.spec.ts` 那条**绝对时刻**断言，这个错会**一路绿到线上** —— 新写的 e2e 只比对了 `registeredCron` 与 `effectiveAt`，**没有断言锚点绝对时刻**
- **判据：把「写死的常量」换成「读配置」时，先问这个常量原本隐含了哪个基准 / 参照系**，并在替换后回看有没有绝对值的单测能钉住它
