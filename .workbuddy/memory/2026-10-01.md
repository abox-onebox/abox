## 真机首次部署（154.8.164.180）实测 —— 全程踩坑清单
- ⭐ **Ubuntu 镜像默认用户是 `ubuntu` 不是 root**，且腾讯云 Ubuntu **默认禁用 root 口令登录** ⇒ 要 SSH 必须给用户名+密码，`sudo -S` 提权。
- ⚠️ **本机出网被限**：`get.docker.com` / `github.com` **全程超时**；可用源只有
  `mirrors.tencentyun.com`（apt）、`mirrors.cloud.tencent.com/docker-ce`（docker-ce + compose/buildx 插件）、
  `registry.npmjs.org`（200 可用）、Docker Hub 走 registry-mirror `mirror.ccs.tencentyun.com`。
  ⇒ **境外源一律先 curl 探活再写进脚本**，别照抄官方安装文档。
- ⚠️ **`apt install docker.io` 不带 `docker compose`** ⇒ 必须另装 `docker-compose-plugin`（装到 Compose v5.5.1）。
- ⚠️⚠️ **Dockerfile 用了 `RUN --mount=type=cache` ⇒ 必须 BuildKit + buildx**：
  只在 `daemon.json` 开 `features.buildkit` 仍报 "buildx component is missing"，必须装 `docker-buildx-plugin`（v0.37.1）。
- ⚠️⚠️ **仓库真缺陷（真机才暴露）**：根 `package.json` 有 `"prepare": "node scripts/setup-husky.mjs"`，
  但 Dockerfile **只 COPY package.json、不 COPY `scripts/`** ⇒ `pnpm install` 在容器里
  `Cannot find module '/app/scripts/setup-husky.mjs'` 直接 exit 1。
  （`setup-husky.mjs` 自身 try/catch 永不失败，**缺文件才是问题**。）
  临时解法：部署副本上把 `scripts.prepare` 摘掉后重建即过。**根治待修**（COPY scripts/ 或让 prepare 判断存在性）。
- ⚠️ **别用 `pkill -f deploy.sh`**：它会把自己所在的那个 shell 一起杀掉，表现为 `SSHRC=-1` 且**无任何输出**（伪装成失败）。
- ⚠️ `docker compose exec` 必须带 `-f docker-compose.prod.yml`；否则报 "service mysql is not running"。直接 `docker exec abox-*-prod` 更稳。
- ⚠️ **seed 两道闸**：`NODE_ENV=production` 拒绝导入 + 需 `ABOX_SEED_CONFIRM=1` ⇒
  一次性绕过写法 `docker exec -e NODE_ENV=development -e ABOX_SEED_CONFIRM=1 abox-api-prod sh -c '...seed.js'`。
- ⚠️ 脚本输出被 `tail -N` 截断会**漏掉生成的口令** ⇒ 抓口令用 `grep -i -E '口令|pass'` 不要 tail。
