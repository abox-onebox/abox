## 三十、按功能项放权 + 机器人试跑台 + 三个「门禁全绿但功能是死的」缺陷（2026-11-01 深夜）

承接 §二十九。老板要的是「我能用全部功能，部分敏感功能放权给同事」。
上一批只有 owner/staff 两档，表达不了「张三能批退款、李四不能」。

### ① 放权模型（`granted_ops` · 迁移 1700000000023）
- **两个概念必须分开**：`tier` = 执行身份（用哪个服务账号打后台）；
  `grantedOps` = 单独放权的端点白名单，只对 staff 有意义。
- ⭐ 语义是**加号**：空 = 他保留 operator 本来的能力；有编码 = 这些端点额外允许。
  ⇒ 收回（置空）是安全动作，不会把人做废。若做成减号，收回会直接干废同事。
- ⭐⭐ **关键难点**：被放权的端点（如退款审批）`@Roles` 里**没有 operator**，
  用 operator 令牌打过去后台 403 ⇒ 现象是「后台点了放权、机器人还说做不了」。
  ⇒ 清单非空时必须把执行身份升到 owner，限制改由清单逐条判。
- 安全靠两道，同源判据 `op-policy`：
  · `execCatalog` 入口判一次（**收回后已生成的草稿也立刻失效** —— 聊天层判过不算数）；
  · 展示层（目录/搜索/计数）按同一清单过滤，不出现「看得见点不了」。
- 判据要点：`isGranted` 只认**精确编码**；`opts.code` 缺失时**不放行**
  （防止调用方忘传参 → 静默变成全通）。

### ② 机器人试跑台（`POST /api/v1/admin/wecom-kb/simulate`）
企微回调要域名、备案没过 ⇒ 机器人在真实环境里**一次都没被跑通过**。
试跑台走服务端**同一套** `WecomChatService.reply()` 与执行通道，不是另写的模拟器。
⚠️ 它会**真的写库**（不是沙箱）：页面明确标注，审计 `X-KB-Operator` 记当前管理员姓名。

### ③ ⛔⛔ 三个叠加缺陷：门禁全绿，功能全死
上线后带 token 一打才发现，此前**验收方式本身是错的**（只测了「无 token → 10002」，
看起来像「路由存在只是要登录」）。真因三条，同源：

1. **JWT 作用域**：`ADMIN_SCOPE` 只认 `/admin`、`/supplier` 开头。
   管理端点写成 `/wecom/kb/...`（为和回调凑一组）⇒ 被判「用户端」⇒
   后台 token 一进来就 `10002 后台账号请使用后台接口`。
2. **body 解析**：`main.ts` 关了默认 bodyParser，自定义中间件只挂 `/api/v1/*`
   ⇒ `/wecom/*` 的 `req.body` 恒 `undefined` ⇒ 写入全回 `10001 参数校验失败`。
3. **实体未注册**：`database.module` 用**显式清单** `entities: ALL_ENTITIES`
   （不是 `autoLoadEntities`），`WecomBinding` 从没进去
   ⇒ 运行时 `No metadata for "WecomBinding"` ⇒ 列表 500。
   ⚠️ 连带后果：`schema:parity` / `index:parity` **根本不检查这张表**，
   它一直在 `MIGRATION_ONLY_EXEMPT` 豁免里（门禁有「豁免腐烂」自检，注册后要求删条目）。

**修法不是打补丁，是归位**：管理端点全部搬到 `/api/v1/admin/wecom-kb/{bindings,ops,simulate}`，
只有回调 `/wecom/kb/callback` 保留免前缀（那是企微侧配的地址）。
`WECOM_ADMIN_SCOPE` 例外表随之删除 —— 不留两套规则。

⭐⭐ **教训（写进跨轮纪律级）**：
- 「免前缀」不只是地址问题，**会连带丢掉 body 解析、主体判定、限流**三样。
- 验收必须**带真 token 打一次写接口**；只测「无 token 返回什么」等于没测。
- 新增实体必须进 `ALL_ENTITIES`，否则 schema/index 两道闸对它完全沉默。
