三、如何手动验证

先部署（两端都要重新构建）

  1. 后端：在 154.8.164.180 上 docker compose build api && docker compose up -d api（新增了 /admin/users 与 20016，不重建不会出现）。
  2. 小程序：pnpm run build:mp，再用微信开发者工具打开 dist/build/mp-weixin 预览（AppID 已写在 mp-weixin.appid）。

小程序端

  1. 用一个未绑楼的账号进首页 → 应显示「你还没有选择办公楼」，主按钮是「选择办公楼」（不再是「本楼今日未开团 / 重新加载」）。
  2. 点该按钮 → 进入选楼页 → 列表只出现营业中的楼，每栋楼显示其团长；选一栋 → 自动返回。
  3. 回首页应正常展示次日套餐；若该楼无团长，选楼时应先弹窗提示。
  4. 「我的 → 切换办公楼」走同一页；换楼后首页内容应跟着变（原团长关系会清空，这是预期）。

运营后台

  1. 登录后台 → 左侧新增「用户」分组 → 打开用户列表；顶部应出现「未绑楼 N 人」警示（N 与实际一致）。
  2. 用「绑定状态 = 未绑定」筛选 → 结果应全是未绑楼用户，与警示数字对得上。
  3. 点任一行 → 详情抽屉：基本信息、余额（走 LeaderMoneyService）、最近 10 单，以及一段「为什么不能下单」的归因说明。
  4. 点「编辑」→ 改绑另一栋楼（或清空 = 解绑）→ 解绑时有二次确认；保存后列表该行应立刻变化。
  5. 已注销（status=3）的用户编辑按钮应不可点 —— 注销不可逆，不由运营代劳。
  6. 「系统 → 队列状态」：看驱动是否为 redis、durable 是否为 true；若显示 memory / durable=false 会有一条红色警示（生产不应如此）。
