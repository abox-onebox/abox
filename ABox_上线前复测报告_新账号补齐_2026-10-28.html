一处口径差异（非缺陷，但要知会）

停用团长后下单返回的是 30007「未绑定团长，请通过团长邀请链接进入」，不是预期里的 60010。

原因：suspend 会清掉用户归属团长（user.team_leader_id），用户因此落到「未绑定团长」分支，而非「团长已停用」分支。功能上拦住了，但文案对老用户不友好——昨天还下过单的人，今天突然被要求"通过邀请链接进入"。

建议：停用属例外处置（违规），频率低。若要改，应在「用户曾有归属团长但团长已停用」时给单独文案；可列为上线后优化项，不阻断。

五、B1 的修复方案（二选一，建议 A）

方案 A · 修 nginx（推荐，治本）

把闸门生效点从 server 级 挪进 location /，让 /api/ 与 /static/ 不再受它管辖（安全性仍由 JWT 保证）：

  1. 删除 apps/miniprogram/nginx.conf 第 113–115 行：
    if ($abox_gate_pass = 0) { return 401; }
  2. 在 location / 块（第 220–231 行）内，if ($abox_gate_grant = 1) 之后、try_files 之前，补一句：
    if ($abox_gate_pass = 0) { return 401; }

副作用核对：location ~* ^/api/v1/pay/mock/paid 是正则 location，优先级高于前缀 location /，因此 mock/paid 的 404 拦截不受影响（反而更干净——原先 401 盖住了 404，等于告诉探测者"这里有东西"）。

把小程序 apiBaseUrl 从 8081 改到 8080（8080 与 8081 同样反代 /api/ → api:3000，本轮全部接口实测走 8080 均通），重新构建并上传体验版。
