## 一、⛔ 先解决这个死结：`PROVIDER_MODE`（不做完，后面全是空转）

### 1.1 死结的形状

三件事同时为真，构成**两条路都走不通**：

| # | 事实                                                    | 出处                                                                          |
| - | ----------------------------------------------------- | --------------------------------------------------------------------------- |
| ① | 生产 + `PROVIDER_MODE=mock` ⇒ **启动即 `process.exit(1)`** | `apps/api-server/src/common/utils/prod-mock-gate.ts:76-116` + `main.ts:107` |
| ② | 生产默认值已改 `real`，且 `PROVIDER_MODE` 在生产必配清单里             | `app.config.ts:33` + `main.ts` `REQUIRED_IN_PROD`                           |
| ③ | `real` 分支的**下单 / 退款 / 回调三条全是 `notReady()` 抛错桩**       | `providers/wx-pay/real-wx-pay.provider.ts:58/62/66`                         |

⇒ **配 `real` = 所有实付 > 0 的订单（也就是默认那笔 ¥25.80）下单即失败；开 `ALLOW_MOCK_IN_PROD=1` 逃生 = 免密登录任意身份 + 自动置为已支付 + 免鉴权改单口子敞开。没有第三条路。**

### 1.2 ⚠️ 更危险的一条：退款

`order.service.ts:617-621` 是「**事务内**先冲销 + 退余额，**事务外**才调支付通道」。  
⇒ 通道抛错后：**余额已退、账务已冲销、微信那边的钱永远退不回**，退款单卡 `failed`，重试 3 次后进死信。

> 线上真退款是硬需求，目前 **0 真实实现**。这一条不是「降级」，是**资金事故**。

### 1.3 怎么解（按推荐度）

| 方案          | 做法                                                                                              | 评价                                                                                                                                |
| ----------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **A ✅ 推荐**  | 补全 `RealWxPayProvider` 三条实现（SDK `wechatpay-node-v3` **已安装但未 import**），在**测试商户**跑通回调验签，再切 `real` | 唯一正解。注释自估约 0.5 人天                                                                                                                 |
| **B ⛔ 不推荐** | 生产留 `ALLOW_MOCK_IN_PROD=1`                                                                      | 任何人 `POST /auth/login {code:"dev:1001"}` 免密登录任意身份；`POST /pay/mock/paid` 是 `@Public()` 且唯一防线 `!isMock` 在 mock 下恒不成立 ⇒ **资金与身份双失守** |
| **C 🟡 过渡** | **提审环境单独一套，`NODE_ENV` 不设 `production`**（如 `staging`）⇒ 硬闸不拦，可继续用 mock 走免支付审核                     | 只用于**提审阶段**。⚠️《提审说明 v1.0》原本写「体验版 + MOCK 模式」，与新硬闸**直接冲突**，方案 C 是让这两者重新兼容的唯一干净做法                                                    |

### 1.4 ⚠️ 顺带必须修的：回调验签是空壳

`common/guards/wx-signature.guard.ts:14` 内容**只有 `export {}`**，全仓 **0 引用**；  
而 `payment.controller.ts:48` 的注释却写着「real 模式下由 `wx-signature.guard` 校验收款签名」——**注释失真**。  
⇒ 补全 `real` 时**必须同时补验签**，否则 `POST /pay/notify`（`@Public()`）是一个**免鉴权改单入口**。

### 2C-0 ⭐ 域名规划专项（买域名之前先定这个）

**两个对外入口，建议拆成两个子域，不要混：**

| 入口              | 建议域名         | 谁访问          | 暴露面           |
| --------------- | ------------ | ------------ | ------------- |
| API（小程序用）       | `api.<域名>`   | **公网**（所有用户） | 必须公网可达        |
| 运营后台（admin-web） | `admin.<域名>` | 只应运营人员访问     | ⛔ **不该无门槛暴露** |

**为什么必须拆**：现在 8080 上挂的 nginx **同时**提供后台页面 + `/api/` 反代（`nginx.conf:34-35`）。

如果只用一个域名、让宿主 nginx 把 `/` 或 `/admin/` 也转发到 8080，就等于**把运营后台挂在公网同一个门牌下** —— 后台有资金操作（退款审批 / 提现审批 / 强制退款）。

**拆开之后的两个额外好处**：

1. **后台可以只对内网/VPN 或 IP 白名单开放**，公网 DNS 甚至可以不解析 `admin.<域名>`；
2. ⭐ **admin 前端一行代码都不用改** —— `apps/admin-web/src/utils/request.ts:40` 的 `baseURL` 默认就是同源相对路径 `/api/v1`，拆域后同源关系不变。**只有小程序端需要改 `.env` 重构建**（P0-1）。

**⚠️ 拆域解决不了的一条（如实标注为未解决）**：`nginx.conf:52-53` 的 `location /static/ → http://api:3000` 是**无鉴权直出**。后台上传的商品图/凭证图，任何人拿到 URL 就能打开，不需要登录。缓解手段只有「URL 不可猜」+ 后续接 CDN 鉴权，**一期不做**。  
⭐ **⛔ 但千万别在反代层把 `/static/` 封掉** —— `main.ts:212` 挂的是 **api 的上传目录**（菜品图 / 凭证图），**不是 admin 自身的 js/css**（那些走 `/assets/`）⇒ 一封就把**菜品图全打死**，而这个后果只在页面上看图时才暴露。  
⚠️ 别把它和 `storage.local.publicBase` 兜底 `http://localhost:3000/static`（`storage.config.ts:35`）混为一谈：**那条是「URL 下发出去就错」，这条是「文件本身无鉴权」**，是两件事。  
⚠️ 「文件名带哈希 ⇒ 不可猜测」**没有验到**（未找到哈希生成点）⇒ **别把它当防线**

**🔴 但这一条现在是「现状风险」，不是「规划时要考虑的」**：  
`docker-compose.prod.yml:140` 把 admin 的 80 直接映射到宿主 **8080**，而 8080 **当前就是公网可达的**（安全组已放行）。  
⇒ **此刻**任何人访问 `http://154.8.164.180:8080/` 就能打开运营后台登录页（有资金操作：退款审批 / 提现审批 / 强制退款；`/static/` 还无鉴权直出）。  
⇒ 阶段 0 做完「放行 8081」之后，请**顺手把 8080 也收口**：要么只监听 `127.0.0.1` 交给宿主 nginx，要么加 IP 白名单。**不要等到 C 线做完才处理**。
