四、阻断上线的缺陷

订单详情／支付结果接口持续不可用

服务端返回：

{"code":10001,"message":"Unexpected token '\"', \"\"eyJhbGciO\"... is not valid JSON"}

影响面（已确认）：

  • GET /orders/:orderNo（订单详情）与 GET /orders/:orderNo/pay-result（支付结果）— 全部失败
  • GET /orders（订单列表）— 完全正常
  • 不限于某个账号：全新注册用户、从未做过任何异常操作的订单，同样失败
  • 不限于某笔订单：连续新建多笔订单全部失败（10/10）
  • 连续观察 6 次共 100 秒（16:37:05 → 16:38:45）始终未恢复
  • 健康检查正常（db 1ms、队列 ok），监控发现不了

今天观察到的时间线：15:41 前后首次出现，期间几度自愈（自愈后功能完全正常），16:31 起转为持续失败至今。「能自愈」正是它危险的地方——容易被当成偶发抖动忽略，而它复发时直接影响用户查看订单。

给技术的复现路径（任何账号都能复现，不需要特殊环境）：

1) POST /api/v1/auth/login    body: {"code":"dev:任意新编号"}
2) PUT  /api/v1/me/building    body: {"buildingId":1}
3) POST /api/v1/orders         body: {"quantity":1}   header: Idempotency-Key: 随机UUID
   → 返回 orderNo
4) GET  /api/v1/orders/{orderNo}            ← 必返 10001
   GET  /api/v1/orders/{orderNo}/pay-result ← 必返 10001
   GET  /api/v1/orders?page=1&pageSize=3    ← 正常 code=0

排查建议：错误信息表明服务端在把一段 JWT 字符串当 JSON 解析（eyJhbGciO 是 JWT 头部）。列表正常而详情失败，说明两者走了不同的数据装配路径，详情侧某处读到的缓存值被写成了 JWT 形状。建议检索 JSON.parse 调用点并检查对应缓存键的实际内容。

六、其他发现（非阻断，建议处置）

P1 · 停用阈值实际为 0，导致部分场景测不出来

代码内置默认为 20（biz-config.service.ts:183），但线上实测 1 笔未完结订单即触发 60012：判据是 total > threshold，1 笔触发即说明阈值实际为 0。

连带影响：阈值 0 时，只要有未完结订单就一定走 60012（需运营审批），60006／60007 永远不会出现，forceSuspend 逃生舱也永远不会放行。而测试文档是按「默认 20」写的，测试人员造不出文档描述的场景。

建议：确认线上 building.suspend_force_max_count 的期望值（保持 0 即严格审批，或调回预期数字），并同步更新测试文档。

P1 · nginx 对模拟支付的封锁可被大小写绕过

POST /api/v1/pay/mock/paid  -> nginx 404（已封锁）
POST /api/v1/pay/MOCK/paid  -> 201 {"code":0}  ← 真实执行成功

NestJS 路由大小写不敏感，故大小写与尾斜杠均能绕过。本环境 PROVIDER_MODE=mock、mockEscaped=true，该接口作用是免鉴权把订单改成已支付。建议 nginx 规则改为不区分大小写，或由应用层 prod-mock-gate 关闭。

P2 · 并发下可生成多笔待支付订单

同一用户用不同幂等键并发下单 5 次，成功生成 5 笔。目前只有单笔份数上限（order.max_quantity=20），没有同一用户同一出餐日的订单笔数上限，可能造成履约混乱，请确认是否需要限制。

七、测试环境的重要事实（避免误判）

现象 说明
下单后会自动变成「已支付」 mock 模式默认开启自动支付（延迟 800ms）。这是环境特性不是 bug——测试人员若不知道，会误以为「没付钱怎么就付款了」
无团长的楼下不了单 返回 30007 LEADER_NOT_FOUND，属正确拦截
绑定待开通／暂停的楼会失败 返回 60001「XX」暂未开通，请选择列表中的其他办公楼，第一道闸门有效
取消原因必须是指定枚举 not_in_office／dish_dislike／price／delivery_time／ate_elsewhere／duplicate／other，否则 10001
线上形态 健康检查实读 providerMode: mock、mockEscaped: true。这是「任意 code 免鉴权登录任意身份 + 免鉴权改支付状态」的形态，测试环境可接受，正式环境必须为 real
