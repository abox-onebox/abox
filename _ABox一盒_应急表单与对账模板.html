三条铁律（贯穿本模板）：
① 只供单一套餐 ⇒ 严禁用户侧出现「选口味 / 选餐 / 备注」类输入字段（曾误加"微辣"选框，违背本意且拖效率）；但当日套餐内容（一饭四菜）必须作为只读信息展示，让用户看到今天吃什么、避免盲订。
② 交付 = 团长取餐并送上楼、团员零走动 ⇒ 文案绝无「自提点 / 用户自提 / 自行领取」字样。
③ 用户表单只填 份数 一项；身份靠表单工具自动记提交人（昵称 / 微信号）+ 团长认识同事认领，全程不收集真实姓名。不要求用户选「推荐团长」（表单归属靠团长专属链接自动完成）。

隐私说明：应急期我们不收集用户的真实姓名。你是谁，团长本来认识；表单工具（腾讯文档 / 群接龙）也会自动记下「谁提交的」，团长据此认领即可。

一、团长专属表单（每个团长一个，自动归属）

核心思路：一个团长 = 一个专属表单 / 一条专属链接。用户点的是「某团长发来的表单」，里面的人天然就是他推荐的，不需要用户再选团长。表单只收用户填的「份数」一项——身份不靠用户手填，靠表单工具自动记提交人 + 团长认识同事，所以连姓名都不用问。

1.1 表单设置要点（照着勾）

  • 标题：「ABox一盒 · 团长名 今日订餐」（例：ABox一盒 · 张姐 今日订餐）
  • 收集截止：当天 24:00（对应 T-1 截单；逾期表单自动关）
  • 权限：仅团队成员可填 / 拿到链接可填（按你们习惯）
  • 必填校验：份数 设必填（默认 1）
  • 归属字段：表单本身挂在团长账号下 + 标题带团长名 ⇒ 无需用户选团长
  • 身份字段：不单独设姓名项——腾讯文档 / 群接龙会自动记录提交人（昵称 / 微信号），团长认识同事，看到即认领
  • 菜品展示（只读，非填写项）：表单顶部固定一块「今日一饭四菜」，由运营 / 团长每日更新当天菜名（可配图）。用户只看不填——知道今天吃什么，但不让选。
  • 说明区（表单顶部）：放一段极简说明 + 商家收款码图片（见下方话术）

1.2 用户要填的字段（仅「份数」一项；今日菜品是展示不是填写）

1.3 可直接复制的「字段配置文本」

把下面的文字直接粘进表单工具的「说明 / 题目」里即可，不用二次设计：

【ABox一盒 · 今日订餐】 我们是一盒现做盒饭（单一套餐，一饭四菜），明天 11:30 前团长会直接把餐送到你工位，你不用下楼。 【今日一饭四菜 · 只读展示，运营每日更新】 主食：［填入］ 主菜：［填入］ 素菜：［填入］ 汤品：［填入］ 凉菜：［填入］ （今日统一配，不可选——先看今天吃什么再决定订几份） 请填写： 1. 份数（必填，默认 1 份） 我们不收集你的真实姓名——你是谁，表单会自动记下提交人、团长也都认识，放心填。 填完后请扫下方商家收款码付款，付款备注写你的昵称即可（非强制，方便团长核对）。 （收款码图片放这里） 截止时间：今天 24:00，逾期表单关闭，明天统一配送。

二、团长-商家对账表（按团长归集份数与金额）

每天收班后，每个团长把自己表单的「订份数」报给你（或导出表单），你填进下表。团长只报数、不碰钱——用户直接付商家收款码，钱不过团长手。恢复小程序后，凭此表批量补录、照常结算佣金。

资金红线：应急期严禁团长用个人码「代收后转账」，避免形成资金池（税务 / 合规 / 信任风险）。用户一律扫商家官方收款码直接付款，团长只收集份数（不碰真实姓名）。

2.2 公式说明（建表时直接写公式）

  • 应收总额 = 表单订份数 × 25.80
  • 团长佣金 = 应收总额 × 佣金比例（见习 8% / 正式 9% / 金牌 10% / 首席 12%）
  • 商家实收 = 应收总额 − 团长佣金
  • 实送份数：默认 = 表单订份数；若有临时取消，按实际送达填，差额不结算佣金
  • 「表单订份数」来源：表单工具一键导出份数列 + 提交人昵称（自动记录），直接 COUNT 份数即可，无需手抄

三、小程序恢复后的切换清单（简版）

  • ① 停发应急表单与收款码，群内发「恢复通知」：以后回到小程序下单，体验更顺。
  • ② 把应急期对账表按日期批量补录系统，佣金照常结算，不漏不掉。
  • ③ 给应急期下单用户发一张补偿券，把流失风险压到最低。
  • ④ 复盘：哪些团长建了常点用户小群、触达效率更高，作为长期优化方向。
